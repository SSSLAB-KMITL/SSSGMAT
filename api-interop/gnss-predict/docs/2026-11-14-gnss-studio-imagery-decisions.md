## การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. ผู้ใช้เลือก "ทาง ข" แล้วลงมือทันทีโดยไม่รอตรวจ spec — ผู้ใช้ชอบให้ทำแล้วรายงาน — แก้ตามที่ผู้ใช้เปลี่ยน
2. ดาวกล้องเป็น object (Himawari, GOES, Terra ฯลฯ) แยกไปงาน ข2 — ต้องแก้ engine ให้รองรับดาวที่ไม่ใช่ GNSS — ผู้ใช้ยังดูภาพจากตำแหน่งดาวกล้องไม่ได้ในรอบนี้
3. ไม่อ่าน GetCapabilities ระหว่างใช้งาน ใช้ผล 4xx ต่อชิ้นแทน — ลดการต่อเน็ตและการ parse XML ที่ไม่น่าเชื่อถือ — บอกช่วงเวลาที่มีภาพล่วงหน้าไม่ได้
4. ตัวเปิดการเชื่อมต่อของ server ปฏิเสธ redirect ทุกกรณี — กันการถูกพาไปโฮสต์อื่น — ไม่มี
5. คำขอที่เจอ 403/429 จาก GIBS ตอบ 502 และคำขอถัดไปตอบ 503 `IMAGERY_PAUSED`; 403/429 ไม่นับในตัวนับ 20 ครั้ง — การพัก 15 นาทีครอบคลุมแล้ว — รหัสสถานะต่างไป 1 ตัว
6. ชั้นคงที่ (Blue Marble) ใช้ Time = `default` ตามแม่แบบ URL — รอยืนยันกับ GIBS จริง (B0) — ชั้นนี้อาจโหลดไม่ขึ้นจนกว่าจะแก้ `upstream_url`
7. เปลี่ยนเวลาภาพแล้วคงชั้นเก่าไว้ใต้ชั้นใหม่จนชั้นใหม่โหลดชิ้นแรก (ไม่เกิน 2 ชั้นต่อ id) — ไม่ให้ภาพกะพริบดำ — อาจเห็น Natural Earth เป็นหย่อมสั้น ๆ
8. หน้าเว็บได้ 403 จากชิ้นภาพ = ปิดชั้น GIBS ในเครื่อง (ไม่ PUT); 404 = ไม่มีภาพ; อย่างอื่นไม่นับ ไม่ลองซ้ำ — server ตอบ 403 เฉพาะสวิตช์ปิด — สัดส่วนบน HUD คลาดเล็กน้อย
9. สัดส่วน "ไม่มีภาพ" บน HUD หารด้วยชิ้นที่ได้ผลแล้ว ไม่ใช่ชิ้นที่ขอ — ไม่นับชิ้นที่กำลังโหลด — ข้อความขึ้นเร็วขึ้นเล็กน้อย
10. เมนู "Globe Manager" ไม่มี "..." — เป็นคำ STK ตรงตัว (STK ref §H) — แค่หน้าตา
11. ยกข้อเล็กขึ้นมาแก้ในรอบตรวจรวม: ชั้น GIBS มืดตาม Ambient Level, HUD บอกเวลาของภาพที่เห็นจริง, เครดิต NASA/JMA/NOAA บนจอ,
    ข้อความยืนยันบอกว่า IP และ User-Agent ถึง NASA ด้วย — ผู้ใช้เห็นได้และเป็นเรื่องความตรงไปตรงมา — diff เพิ่มเล็กน้อย
12. ไม่แก้: ติ๊กสวิตช์ใน Globe Manager อาจเขียนทับ `settings.json` ที่แก้มือจนผิดรูป (ได้ค่าปลอดภัย daily ปิด); สวิตช์ที่เปลี่ยนจากอีกแท็บไม่เห็นจนโหลดใหม่ — ทิศทางปลอดภัย — ค่าที่แก้มือหาย
13. ลูกล้อแบบบรรทัด/หน้า นับอย่างน้อย 100 px ต่อครั้ง — ให้ล้อ Firefox หนึ่งจังหวะซูมได้ — ไม่มี
14. ชิ้นภาพที่ยังไม่นิ่ง (รายวันของวันนี้/เมื่อวาน, 10 นาทีของ 3 ชั่วโมงล่าสุด, อนาคต) ไม่เก็บลงดิสก์ — GIBS ยังเติมภาพไม่ครบ ภาพเก่าจะค้าง — ดึงซ้ำบ่อยขึ้นสำหรับช่วงล่าสุด

- [spec](2026-11-14-gnss-studio-hires-imagery-design.md), [แผน](2026-11-14-gnss-studio-hires-imagery-plan.md) (อ้างว่า "ภาพละเอียด spec §n"), ต่อยอด [spec ภาพ GIBS](2026-11-14-gnss-studio-imagery-design.md)
- ลงมือแบบ subagent-driven เหมือน ข: 5 งาน งาน 1-4 มีผู้ตรวจแยก
- ผู้ใช้เลือก "เอาทั้ง a b c" (2026-11-14) = Sentinel-2 cloudless (EOX), OpenStreetMap, Cesium ion พร้อมกัน แต่ละแหล่งมีสวิตช์และกล่องยืนยันของตัวเอง ปิดเป็นค่าตั้งต้น

### การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. งาน 1: ชั้นที่ไม่รู้จักตอบ 403 เฉพาะเมื่อ GIBS และ EOX ปิดทั้งคู่ ไม่งั้นตอบ 404 — ชั้นที่ไม่รู้จักไม่มีแหล่งให้ดูสวิตช์ และต้องคงหลัก "ปิด = 403" — รหัสสถานะต่างไป 1 ตัว
2. งาน 1: regex พิกัดชิ้นภาพกว้างขึ้นเป็น 5 หลัก — EOX ระดับ 15 มี x, y ถึง 32767 — ไม่มี
3. งาน 2: ชั้น ion "แสดง" = สวิตช์ ion เปิด + เลือก asset แล้ว + token ไม่ว่าง; asset เป็น null = ไม่แสดง (ไม่มีแถว Show) จึงต้องมีตัวเลือก "ไม่เลือก" ใน radio — ไม่มี asset ก็ไม่มีภาพให้ซ่อนชั้นอื่น — ต้องแก้ UI ในงาน 3 (งาน 3 ทำตัวเลือก "ไม่เลือก" ให้แล้ว)
4. งาน 2: workbook ใหม่ตั้งแถว EOX และ OSM เป็นแสดงไว้ก่อน (สวิตช์ของแหล่งยังปิดจึงยังไม่มีภาพ) workbook เก่าคงซ่อน — เปิดสวิตช์ของแหล่งแล้วมีภาพทันที — ค่าตั้งต้นหนึ่งค่า
5. งาน 2: ตัด `useImagery.enabled` / `setEnabled` ออก ใช้ `sources` / `setSource` ที่เดียว — API เดียวสำหรับสี่แหล่ง — ไม่มี
6. งาน 2: **ส่งต่อรอบแก้สุดท้าย (ยังไม่ทำ)** ชิ้น ion ล้มเหลวเกินเกณฑ์ = `failIon` (ข้อความไทย คืนภาพฐาน), ชิ้น OSM ล้มเหลวต่อเนื่อง = ข้อความไทย (spec §5), และล้าง `ionFailure` เมื่อแผนเปลี่ยนโดยไม่ต้องมี viewer ติดอยู่ — ตอนนี้ถ้า ion ตอบชิ้นล้มเหลวทั้งหมด หน้าจอดำโดยไม่บอก และ OSM ที่ถูกบล็อกเงียบ — diff เล็ก
7. งาน 3: ย้ายแผน สถานะ และความล้มเหลวของ ion ไปไฟล์ `cesium/ionState.ts` (ไม่ import Cesium) — Globe Manager ต้องไม่ลาก chunk ของ Cesium เข้ามา (แยก bundle) — ไม่มี
8. งาน 3: Natural Earth II อยู่ในตารางฐานของตัวเอง นอกกลุ่ม และมีหมายเหตุ "ถูกซ่อนเพราะเปิด Cesium ion อยู่" — ปิดไม่ได้เหมือนเดิม และสอดคล้องกับชั้นอื่น — ไม่มี
9. งาน 4: แก้ `sensorHud()` ใน `scene3d.ts` ราว 6 บรรทัด ให้ส่ง `source`, `max_level`, `shortSidePx` ไป HUD — ตัวสร้างข้อมูล HUD ตัวเดียวและไม่แตะส่วนอื่นของ scene — ไม่มี
10. งาน 4: ข้อความ "ภาพละเอียดสุดของแหล่งนี้แล้ว" ขึ้นเฉพาะชั้น GIBS, EOX, OSM ไม่ขึ้นกับ ion — ระดับสูงสุดของ asset ion ไม่รู้ล่วงหน้า — แคบกว่า spec §4.4 เล็กน้อย; ซูมเกินความละเอียดของ ion จะไม่มีคำเตือน
11. งาน 5: e2e เพิ่มตัวตรวจ request นอกเครื่องในตัว spec (fixture `guards`: ไม่มี request ไป `/api/imagery/tiles` และไม่มี request ไป origin อื่นนอก server ของ e2e) ซ้อนกับตัวกันกลางของ `fixtures.ts` ที่คงไว้ — ให้ spec ภาพประกาศเงื่อนไขของตัวเองและแจ้งชื่อแหล่งในข้อความเมื่อล้ม — โค้ดซ้ำเล็กน้อย
12. งาน 5: ตรวจ "ความกว้างพื้นที่" ใน e2e ด้วยสูตรอิสระ 2·h·tan(fov ด้านสั้น / 2) จากความสูงกล้อง (คลาดไม่เกิน 3%) ไม่เรียกสูตรของแอป — การวัดซ้ำด้วยสูตรเดียวกับโค้ดที่ทดสอบไม่ตรวจอะไร (ที่ fov ≤ 2° สองสูตรต่างกันไม่ถึง 1%) — เกณฑ์ 3% หลวมกว่าสูตรจริง
13. งาน 5: เปลี่ยนชื่อหัวข้อ README 8.8 และ 9.10 ให้ครอบคลุมสี่แหล่ง (ลิงก์ anchor ภายในแก้ตาม) และแก้ตัวอย่าง `PUT /api/settings` ใน 8.3 ให้ส่งครบสี่ช่อง — ตัวอย่างเดิมจะได้ 422 — ลิงก์ภายนอกที่ชี้หัวข้อเดิมเสีย (ไม่พบในที่ใดของ repo)

### เรื่องที่ผู้ใช้ควรรู้

- **ทุกแหล่งปิดเป็นค่าตั้งต้น** (รวม `settings.json` เก่าที่มีแต่ `enabled`) เปิดแต่ละแหล่งต้องผ่านกล่องยืนยันภาษาไทยของแหล่งนั้น ปิดแล้วไม่มี request ไปโฮสต์นั้นเลย ทั้งจาก server และจาก browser
- **OpenStreetMap และ Cesium ion browser ดึงเองโดยตรง** (โฮสต์เห็น IP, User-Agent และ Referer `http://127.0.0.1:<port>/`; ion เห็น token ของคุณด้วย) ส่วน GIBS และ EOX ยังผ่าน server ในเครื่อง
- **Cesium ion แสดงภาพ = ชั้นอื่นทั้งหมดถูกซ่อน** (รวม Natural Earth II) จนกว่าจะปิด ion ภาพ Bing และ Google ห้ามซ้อนกับภาพแหล่งอื่น ปิด ion แล้วทุกอย่างกลับเหมือนเดิม
- **token ของ Cesium ion** เก็บเป็นข้อความธรรมดาใน `data/settings.json` (git ละเว้น) ตั้งได้ที่ Globe Manager หรือ Daily Forecast Settings อย่าใส่ใน repo หรือ test; บัญชี Community ใช้ได้เฉพาะงานไม่เชิงพาณิชย์ และ Sentinel-2 cloudless (EOX) ก็ใช้ได้เฉพาะงานไม่เชิงพาณิชย์เช่นกัน
- **ข้อผูกพันของ OpenStreetMap**: แสดงเครดิต ขอเฉพาะชิ้นที่มองเห็น ไม่โหลดล่วงหน้า ไม่เก็บออฟไลน์ ไม่ส่ง no-cache ไม่ตั้ง Referrer-Policy ที่ตัด Referer และถูกบล็อกได้โดยไม่แจ้ง
- **ยังไม่ได้ยืนยันกับของจริง**: ชั้น EOX (ชื่อชั้น `s2cloudless-2024_3857`, TileMatrixSet `g`, ระดับสูงสุด 15), Asset ID ของ ion และว่าบัญชีของคุณเข้าถึงได้หรือไม่ (Bing บน ion อาจถูกถอดแล้ว), Himawari และ GOES ของ GIBS
  **ยืนยันแล้ว**: GIBS Blue Marble (`default`) และ VIIRS NOAA-20 รายวันได้ชิ้นภาพตอบ 200 จากการที่คุณเปิดสวิตช์ GIBS เองเมื่อ 2026-11-14 แก้ที่ตารางชั้นภาพ (`imagery.py`) และ preset ของ ion (`ionAssets.ts`) ที่เดียวถ้าผิด
- **Sensor View ซูมถึง ×8192**: ดาว GPS ที่ ×1024 กว้างราว 10 km ที่ ×8192 ราว 1.3 km (HUD บอกความกว้างและเตือน "ภาพละเอียดสุดของแหล่งนี้แล้ว" เมื่อภาพของ GIBS/EOX/OSM ไม่ละเอียดพอ) ภาพเป็นแบบแผนที่จำลอง ไม่ใช่สิ่งที่ดาว GNSS ถ่ายได้จริง
- **ยังไม่ทำ (รอรอบแก้สุดท้าย)**: ข้อความไทยเมื่อชิ้นภาพ OSM ล้มเหลวต่อเนื่อง และเมื่อ ion ตอบชิ้นล้มเหลวเกินเกณฑ์ (การตัดสินใจข้อ 6)
