## การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. ผู้ใช้เลือก "ทาง ข" แล้วลงมือทันทีโดยไม่รอตรวจ spec — ผู้ใช้ชอบให้ทำแล้วรายงาน — แก้ตามที่ผู้ใช้เปลี่ยน
2. ดาวกล้องเป็น object (Himawari, GOES, Terra ฯลฯ) แยกไปงาน ข2 — ต้องแก้ engine ให้รองรับดาวที่ไม่ใช่ GNSS — ผู้ใช้ยังดูภาพจากตำแหน่งดาวกล้องไม่ได้ในรอบนี้
3. ไม่อ่าน GetCapabilities ระหว่างใช้งาน ใช้ผล 4xx ต่อชิ้นแทน — ลดการต่อเน็ตและการ parse XML ที่ไม่น่าเชื่อถือ — บอกช่วงเวลาที่มีภาพล่วงหน้าไม่ได้
4. ตัวเปิดการเชื่อมต่อของ server ปฏิเสธ redirect ทุกกรณี — กันการถูกพาไปโฮสต์อื่น — ไม่มี
5. คำขอที่เจอ 403/429 จาก GIBS ตอบ 502 และคำขอถัดไปตอบ 503 `IMAGERY_PAUSED`; 403/429 ไม่นับในตัวนับ 20 ครั้ง — การพัก 15 นาทีครอบคลุมแล้ว — รหัสสถานะต่างไป 1 ตัว
6. ชั้นคงที่ (Blue Marble) ใช้ Time = `default` ตามแม่แบบ URL — รอยืนยันกับ GIBS จริง (B0) — ชั้นนี้อาจโหลดไม่ขึ้นจนกว่าจะแก้ `upstream_url`
7. เปลี่ยนเวลาภาพแล้วคงชั้นเก่าไว้ใต้ชั้นใหม่จนชั้นใหม่โหลดชิ้นแรก (ไม่เกิน 2 ชั้นต่อ id) — ไม่ให้ภาพกะพริบดำ — อาจเห็น Natural Earth เป็นหย่อมสั้น ๆ
8. หน้าเว็บได้ 403 จากชิ้นภาพ = ปิดชั้น GIBS ในเครื่อง (ไม่ PUT); 404 = ไม่มีภาพ; อย่างอื่นไม่นับ ไม่ลองซ้ำ — server ตอบ 403 เฉพาะสวิตช์ปิด — สัดส่วนบน HUD คลาดเล็กน้อย
9. สัดส่วน "ไม่มีภาพ" บน HUD หารด้วยชิ้นที่ได้ผลแล้ว ไม่ใช่ชิ้นที่ขอ — ไม่นับชิ้นที่กำลังโหลด — ข้อความขึ้นเร็วขึ้นเล็กน้อย
10. เมนู "Globe Manager" ไม่มี "..." — เป็นคำ STK ตรงตัว (STK ref §H) — แค่หน้าตา
11. ยกข้อเล็กขึ้นมาแก้ในรอบตรวจรวม: ชั้น GIBS มืดตาม Ambient Level, HUD บอกเวลาของภาพที่เห็นจริง, เครดิต NASA/JMA/NOAA บนจอ,
    ข้อความยืนยันบอกว่า IP และ User-Agent ถึง NASA ด้วย — ผู้ใช้เห็นได้และเป็นเรื่องความตรงไปตรงมา — diff เพิ่มเล็กน้อย
12. ไม่แก้: ติ๊กสวิตช์ใน Globe Manager อาจเขียนทับ `settings.json` ที่แก้มือจนผิดรูป (ได้ค่าปลอดภัย daily ปิด); สวิตช์ที่เปลี่ยนจากอีกแท็บไม่เห็นจนโหลดใหม่ — ทิศทางปลอดภัย — ค่าที่แก้มือหาย
13. ลูกล้อแบบบรรทัด/หน้า นับอย่างน้อย 100 px ต่อครั้ง — ให้ล้อ Firefox หนึ่งจังหวะซูมได้ — ไม่มี
14. ชิ้นภาพที่ยังไม่นิ่ง (รายวันของวันนี้/เมื่อวาน, 10 นาทีของ 3 ชั่วโมงล่าสุด, อนาคต) ไม่เก็บลงดิสก์ — GIBS ยังเติมภาพไม่ครบ ภาพเก่าจะค้าง — ดึงซ้ำบ่อยขึ้นสำหรับช่วงล่าสุด

## ข1.5 ภาพละเอียด (EOX, OSM, Cesium ion)

- Branch เดิม `feature/gnss-studio-imagery` (ต่อจาก f944910) ไม่ merge ไม่ push
- [spec](2026-11-14-gnss-studio-hires-imagery-design.md), [แผน](2026-11-14-gnss-studio-hires-imagery-plan.md) (อ้างว่า "ภาพละเอียด spec §n"), ต่อยอด [spec ภาพ GIBS](2026-11-14-gnss-studio-imagery-design.md)
- ลงมือแบบ subagent-driven เหมือน ข: 5 งาน งาน 1-4 มีผู้ตรวจแยก
- ผู้ใช้เลือก "เอาทั้ง a b c" (2026-11-14) = Sentinel-2 cloudless (EOX), OpenStreetMap, Cesium ion พร้อมกัน แต่ละแหล่งมีสวิตช์และกล่องยืนยันของตัวเอง ปิดเป็นค่าตั้งต้น

### การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. งาน 1: ชั้นที่ไม่รู้จักตอบ 403 เฉพาะเมื่อ GIBS และ EOX ปิดทั้งคู่ ไม่งั้นตอบ 404 — ชั้นที่ไม่รู้จักไม่มีแหล่งให้ดูสวิตช์ และต้องคงหลัก "ปิด = 403" — รหัสสถานะต่างไป 1 ตัว
2. งาน 1: regex พิกัดชิ้นภาพกว้างขึ้นเป็น 5 หลัก — EOX ระดับ 15 มี x, y ถึง 32767 — ไม่มี
3. งาน 2: ชั้น ion "แสดง" = สวิตช์ ion เปิด + เลือก asset แล้ว + token ไม่ว่าง; asset เป็น null = ไม่แสดง (ไม่มีแถว Show) จึงต้องมีตัวเลือก "ไม่เลือก" ใน radio — ไม่มี asset ก็ไม่มีภาพให้ซ่อนชั้นอื่น — ต้องแก้ UI ในงาน 3 (งาน 3 ทำตัวเลือก "ไม่เลือก" ให้แล้ว)
4. งาน 2: workbook ใหม่ตั้งแถว EOX และ OSM เป็นแสดงไว้ก่อน (สวิตช์ของแหล่งยังปิดจึงยังไม่มีภาพ) workbook เก่าคงซ่อน — เปิดสวิตช์ของแหล่งแล้วมีภาพทันที — ค่าตั้งต้นหนึ่งค่า
5. งาน 2: ตัด `useImagery.enabled` / `setEnabled` ออก ใช้ `sources` / `setSource` ที่เดียว — API เดียวสำหรับสี่แหล่ง — ไม่มี
6. งาน 2: ส่งต่อรอบแก้สุดท้าย (**ทำแล้ว** ในรอบแก้หลังตรวจรวม ด้านล่าง) ชิ้น ion ล้มเหลวเกินเกณฑ์ = `failIon` (ข้อความไทย คืนภาพฐาน), ชิ้น OSM ล้มเหลวต่อเนื่อง = ข้อความไทย (spec §5), และล้าง `ionFailure` เมื่อแผนเปลี่ยนโดยไม่ต้องมี viewer ติดอยู่ — ก่อนแก้ ถ้า ion ตอบชิ้นล้มเหลวทั้งหมด หน้าจอดำโดยไม่บอก และ OSM ที่ถูกบล็อกเงียบ — diff เล็ก
14. รอบแก้หลังตรวจรวม: เกณฑ์ "ชิ้นภาพล้มเหลวต่อเนื่อง" ของ OSM และ ion = ได้ผลแล้วอย่างน้อย 8 ชิ้นและล้มเหลวตั้งแต่ 75% (นับทุกข้อผิดพลาด ไม่ว่ามีรหัส HTTP หรือไม่) เกณฑ์เดียวกันทุก viewer — กันการแจ้งเพราะชิ้นพลาดไม่กี่ชิ้นตอนเริ่ม และ Safari ไม่ให้รหัสของ OSM — ถ้าเกณฑ์สูงไป ผู้ใช้รอนานขึ้นอีกไม่กี่ชิ้นก่อนได้ข้อความ
15. รอบแก้หลังตรวจรวม: ลบรายการใน `IonImageryProvider._endpointCache` (ของภายในของ Cesium 1.147 คีย์ = assetId + token + server) เองทุกครั้งที่ ion ล้มเหลว — Cesium ไม่ลบ promise ที่ล้มเหลวเอง การลองใหม่จึงได้ผลเดิมจนโหลดหน้าใหม่ — ถ้า Cesium รุ่นหน้าเปลี่ยนชื่อหรือคีย์ การลองใหม่กลับไปได้ผลเดิม (มี test ที่เทียบคีย์กับ Cesium จริงจะล้มให้รู้)
16. รอบแก้หลังตรวจรวม: ล้อเมาส์/trackpad ไม่เกิน 2 ขั้นต่อการปัด (เงียบเกิน 200 ms = การปัดใหม่) — momentum ของ macOS เคยพาไปราว 10 ขั้นจาก 14 — การหมุนล้อรัวต่อเนื่องก็ได้แค่ 2 ขั้นเช่นกัน (ปุ่ม Zoom In/Out ยังใช้ได้)
7. งาน 3: ย้ายแผน สถานะ และความล้มเหลวของ ion ไปไฟล์ `cesium/ionState.ts` (ไม่ import Cesium) — Globe Manager ต้องไม่ลาก chunk ของ Cesium เข้ามา (แยก bundle) — ไม่มี
8. งาน 3: Natural Earth II อยู่ในตารางฐานของตัวเอง นอกกลุ่ม และมีหมายเหตุ "ถูกซ่อนเพราะเปิด Cesium ion อยู่" — ปิดไม่ได้เหมือนเดิม และสอดคล้องกับชั้นอื่น — ไม่มี
9. งาน 4: แก้ `sensorHud()` ใน `scene3d.ts` ราว 6 บรรทัด ให้ส่ง `source`, `max_level`, `shortSidePx` ไป HUD — ตัวสร้างข้อมูล HUD ตัวเดียวและไม่แตะส่วนอื่นของ scene — ไม่มี
10. งาน 4: ข้อความ "ภาพละเอียดสุดของแหล่งนี้แล้ว" ขึ้นเฉพาะชั้น GIBS, EOX, OSM ไม่ขึ้นกับ ion — ระดับสูงสุดของ asset ion ไม่รู้ล่วงหน้า — แคบกว่า spec §4.4 เล็กน้อย; ซูมเกินความละเอียดของ ion จะไม่มีคำเตือน
11. งาน 5: e2e เพิ่มตัวตรวจ request นอกเครื่องในตัว spec (fixture `guards`: ไม่มี request ไป `/api/imagery/tiles` และไม่มี request ไป origin อื่นนอก server ของ e2e) ซ้อนกับตัวกันกลางของ `fixtures.ts` ที่คงไว้ — ให้ spec ภาพประกาศเงื่อนไขของตัวเองและแจ้งชื่อแหล่งในข้อความเมื่อล้ม — โค้ดซ้ำเล็กน้อย
12. งาน 5: ตรวจ "ความกว้างพื้นที่" ใน e2e ด้วยสูตรอิสระ 2·h·tan(fov ด้านสั้น / 2) จากความสูงกล้อง (คลาดไม่เกิน 3%) ไม่เรียกสูตรของแอป — การวัดซ้ำด้วยสูตรเดียวกับโค้ดที่ทดสอบไม่ตรวจอะไร (ที่ fov ≤ 2° สองสูตรต่างกันไม่ถึง 1%) — เกณฑ์ 3% หลวมกว่าสูตรจริง
13. งาน 5: เปลี่ยนชื่อหัวข้อ README 8.8 และ 9.10 ให้ครอบคลุมสี่แหล่ง (ลิงก์ anchor ภายในแก้ตาม) และแก้ตัวอย่าง `PUT /api/settings` ใน 8.3 ให้ส่งครบสี่ช่อง — ตัวอย่างเดิมจะได้ 422 — ลิงก์ภายนอกที่ชี้หัวข้อเดิมเสีย (ไม่พบในที่ใดของ repo)

### เรื่องที่ผู้ใช้ควรรู้

- **ทุกแหล่งปิดเป็นค่าตั้งต้น** (รวม `settings.json` เก่าที่มีแต่ `enabled`) เปิดแต่ละแหล่งต้องผ่านกล่องยืนยันภาษาไทยของแหล่งนั้น ปิดแล้วไม่มี request ไปโฮสต์นั้นเลย ทั้งจาก server และจาก browser
- **OpenStreetMap และ Cesium ion browser ดึงเองโดยตรง** (โฮสต์เห็น IP, User-Agent และ Referer `http://127.0.0.1:<port>/`; ion เห็น token ของคุณด้วย) ส่วน GIBS และ EOX ยังผ่าน server ในเครื่อง
- **Cesium ion แสดงภาพ = ชั้นอื่นทั้งหมดถูกซ่อน** (รวม Natural Earth II) จนกว่าจะปิด ion ภาพ Bing และ Google ห้ามซ้อนกับภาพแหล่งอื่น ปิด ion แล้วทุกอย่างกลับเหมือนเดิม
- **token ของ Cesium ion** เก็บเป็นข้อความธรรมดาใน `data/settings.json` (git ละเว้น) ตั้งได้ที่ Globe Manager หรือ Daily Forecast Settings อย่าใส่ใน repo หรือ test; บัญชี Community ใช้ได้เฉพาะงานไม่เชิงพาณิชย์ และ Sentinel-2 cloudless (EOX) ก็ใช้ได้เฉพาะงานไม่เชิงพาณิชย์เช่นกัน
- **ข้อผูกพันของ OpenStreetMap**: แสดงเครดิต ขอเฉพาะชิ้นที่มองเห็น ไม่โหลดล่วงหน้า ไม่เก็บออฟไลน์ ไม่ส่ง no-cache ไม่ตั้ง Referrer-Policy ที่ตัด Referer และถูกบล็อกได้โดยไม่แจ้ง
- **ยังไม่ได้ยืนยันกับของจริง**: ชั้น EOX (ชื่อชั้น `s2cloudless-2024_3857`, TileMatrixSet `g`, ระดับสูงสุด 15), Asset ID ของ ion และว่าบัญชีของคุณเข้าถึงได้หรือไม่ (Bing บน ion อาจถูกถอดแล้ว), Himawari และ GOES ของ GIBS
  **ยืนยันแล้ว**: GIBS Blue Marble (`default`) และ VIIRS NOAA-20 รายวันได้ชิ้นภาพตอบ 200 จากการที่คุณเปิดสวิตช์ GIBS เองเมื่อ 2026-11-14 แก้ที่ตารางชั้นภาพ (`imagery.py`) และ preset ของ ion (`ionAssets.ts`) ที่เดียวถ้าผิด
- **Sensor View ซูมถึง ×8192**: ดาว GPS ที่ ×1024 กว้างราว 10 km ที่ ×8192 ราว 1.3 km (HUD บอกความกว้างและเตือน "ภาพละเอียดสุดของแหล่งนี้แล้ว" เมื่อภาพของ GIBS/EOX/OSM ไม่ละเอียดพอ) ภาพเป็นแบบแผนที่จำลอง ไม่ใช่สิ่งที่ดาว GNSS ถ่ายได้จริง
- **ชิ้นภาพล้มเหลว**: ion ที่ชิ้นภาพโหลดไม่ได้เกินเกณฑ์ถูกถอดพร้อมข้อความไทย แล้วภาพอื่นกลับมา (ไม่ค้างเป็นลูกโลกดำ) ; OSM ที่ถูกบล็อกหรือเน็ตหลุดได้ข้อความไทยครั้งเดียวต่อการเปิดหน้า
  ปิดแล้วเปิดสวิตช์ ion, เลือก "ไม่เลือก" แล้วเลือก asset ใหม่ หรือเปลี่ยน token = ลองใหม่จริง (ไม่ต้องโหลดหน้าใหม่)
- **token ของ ion มองเห็นได้ใน devtools**: ตัว Cesium ใส่ token ใน `?access_token=` ของคำขอไป `api.cesium.com` จึงเห็นได้ในแท็บ Network และ log ของ proxy

### รอบแก้หลังตรวจรวม

1. ชิ้นภาพ ion ล้มเหลว: นับชิ้นที่ได้และล้มเหลวของชั้น ion (ทุกรหัส หรือไม่มีรหัส) เกินเกณฑ์ = `failIon` ทุก viewer (ข้อความไทย ถอดชั้น ion คืนชั้นอื่นและ Natural Earth II) HUD บอกสัดส่วนจริง (เดิม 0 เสมอ)
2. ลองใหม่จริง: `failIon` ลบ promise ของ endpoint ที่ Cesium จำไว้ และ `ionState.ts` ลืมการล้มเหลวเมื่อแผนของ ion เปลี่ยน (สวิตช์, asset รวม None, token) แม้ไม่มี viewer ติดอยู่ (ตัดตัวลืมใน Globe Manager ที่ซ้ำออก)
3. OSM ล้มเหลวต่อเนื่อง: นับทุกข้อผิดพลาด (Safari ไม่มีรหัส) เกินเกณฑ์เดียวกัน = ข้อความไทยครั้งเดียวต่อการเปิดหน้า และ HUD บอก "ชิ้นภาพส่วนใหญ่โหลดไม่ได้" ไม่เปลี่ยนวิธีขอชิ้นภาพของ OSM
4. เครดิต OSM เป็นลิงก์ `<a href="https://www.openstreetmap.org/copyright" target="_blank" rel="noopener">` เครดิตอื่นยังเป็นข้อความที่กันอักขระพิเศษ
5. ล้อเมาส์/trackpad ไม่เกิน 2 ขั้นต่อการปัด (การตัดสินใจข้อ 16)
6. "ภาพละเอียดสุดของแหล่งนี้แล้ว" เทียบ `needed − 1 > max_level` เพราะ Cesium เลือกภาพที่ราว 2 พิกเซลต่อจุดภาพ (เดิมเตือนเร็วไปหนึ่งระดับ)
7. คำแนะนำ Globe Manager ขึ้นเมื่อไม่มีชั้นออนไลน์แสดงอยู่จริง (เดิมขึ้นเฉพาะเมื่อปิดทุกสวิตช์ เปิด ion ที่ยังไม่เลือก asset จึงไม่มีคำแนะนำ)
8. Daily Forecast Settings: Apply อ่าน `GET /api/settings` ใหม่ก่อน `PUT` สวิตช์ที่ปิดจากแท็บอื่น, curl หรือแก้ไฟล์จึงไม่ถูกเขียนกลับเป็นเปิด (กติกา token เดิม: ช่องที่ไม่ได้แก้ส่งค่าที่เพิ่งอ่าน)
9. e2e: Cancel/Esc ของกล่องยืนยันทุกครั้งตรวจด้วยว่าไม่มี `PUT /api/settings` และตัดการตรวจ null ที่ซ้ำ
10. README: Cesium ใส่ token ใน `?access_token=` ไป api.cesium.com (เห็นใน devtools และ log ของ proxy), "Globe Manager ไม่แสดงค่าที่บันทึกไว้", พฤติกรรมใหม่ของ ion/OSM เมื่อล้มเหลว, ลิงก์เครดิต OSM และเพดานขั้นของการปัด

ค่าก่อนแก้ (วัดบนสำเนาที่ใช้งานจริง Sensor View เหนือ SE Asia แสดง Blue Marble + VIIRS + Sentinel-2 + OSM): เวลาจนคำขอชิ้นภาพเงียบ
×1 8.6 s, ×64 11.8 s, ×1024 4.3 s, ×8192 4.5 s และราวครึ่งของคำขอชิ้นภาพไปที่ชั้นที่ OSM ทึบทับอยู่ (ค่าหลังแก้ controller เติมเอง)

### การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. ไม่สร้างชั้นที่ถูกบัง: วาดเฉพาะชั้นทึบบนสุดที่แสดงอยู่กับชั้นที่อยู่เหนือมัน ชั้นข้างใต้ไม่มี provider จึงไม่มีคำขอชิ้นภาพ (`isOpaqueLayer` ใน `imageryLayers.ts`) คิดใหม่ทุกครั้งที่ Show / Translucency / สวิตช์เปลี่ยน Natural Earth II คงเป็นฐาน — ชั้นใต้ชั้นทึบมองไม่เห็นอยู่แล้ว — ด้านกลางคืนที่ Ambient Level ต่ำ ชั้นบนจางลง ชั้นข้างใต้ที่ไม่ได้สร้างจึงไม่โผล่ผ่าน (ภาพฐาน Natural Earth II โผล่แทน)
2. ชั้นทึบ = translucency 0 และ (jpg ภาพคงที่ `period = static` หรือ OSM) แคบกว่าที่สั่ง ("jpg ทุกชั้นของ GIBS") — VIIRS/MODIS รายวันไม่มีภาพของเวลาในอนาคต (404 = ชิ้นโปร่งใส) scenario พยากรณ์ล่วงหน้าจึงต้องเห็น Blue Marble ข้างใต้ตามที่ README 9.10 บอกไว้ และ GOES (jpg) กับ Himawari (png) เป็นชั้น 10 นาทีของดาวค้างฟ้าที่เห็นแค่จานโลกของตัวเอง — ค่าตั้งต้น (OSM บนสุด 0%) ยังได้ผลเต็ม; กรณี GIBS อย่างเดียวที่ VIIRS ทับ Blue Marble ยังโหลดทั้งสองชั้นเหมือนเดิม
3. ซูมหรือ Up เปลี่ยน (path และ Display เท่าเดิม) = `updateSensorCamera` แล้วแจ้ง HUD อย่างเดียว ไม่ `restyle` — ทุกขั้นซูมเคยวาด entity ใหม่ทั้งหมด — ไม่มี (Display และ path ยังผ่าน restyle)
4. `globe.tileCacheSize = 1000` ใน Scene3D (หน้าต่าง 3D และ Sensor View ใช้ตัวเดียวกัน) — ค่าตั้งต้นของ Cesium 100 ชิ้น ซูมกลับไปมาต้องโหลดใหม่ — หน่วยความจำ GPU ต่อ viewer มากขึ้น (ไม่เกิน 4 Sensor View + หน้าต่าง 3D)
5. zoom เป็นจำนวนต่อเนื่องใน [1, 262144] ค่าที่ไม่ใช่ตัวเลขจำกัดในช่วง (รวม 0, NaN, สตริง, เกินช่วง) = 1 ไม่ตัดให้อยู่ในช่วง — ตามที่สั่ง และค่าเสียมาจากการแก้มือ — ไม่มี
6. ปุ่มและล้อก้าว ×√2 บนตาราง 2^(k/2) (k = 0..36) โดยไปจุดที่ใกล้ที่สุดในสเกล log ก่อนแล้วจึงก้าว (`zoom.ts` ฟังก์ชันล้วน e2e import ได้) ค่าบนตารางคำนวณตรง (k คู่ = กำลังสองพอดี) ไม่คูณสะสม — ×8192 ที่ 26 คลิกเป็น 8192 พอดี — ค่านอกตาราง (จาก Width) ที่อยู่เกือบกลางระหว่างสองจุด ก้าวออกได้ราว ×1.65 แทน ×√2
7. ป้าย "×n": จำนวนเต็มต่ำกว่า 10000 ตรงตัว, ต่ำกว่า 10 ทศนิยมหนึ่งตำแหน่ง, นอกนั้นปัดเป็นจำนวนเต็ม, ตั้งแต่ 10000 เป็นพันแบบตัดเศษ (×65k ไม่ใช่ ×66k) — ×1024 และ ×8192 ตรงตัวตามตัวอย่าง และ 37 จุดบนตารางได้ป้ายไม่ซ้ำกัน — ป้ายพันตัดเศษต่ำกว่าค่าจริงได้เกือบ 1000
8. FOV ของ HUD: ตั้งแต่ 1° ทศนิยมหนึ่งตำแหน่งเหมือนเดิม ต่ำกว่า 1° เลขนัยสำคัญ 2 ตัวแบบไม่ใช้เลขยกกำลัง — ค่าเดิมที่ ≥ 1° (เช่น 30.2°) ไม่ต้องเปลี่ยน และ ×262144 ได้ `0.00012°` — ×1024 เปลี่ยนจาก `0.0295` เป็น `0.030`
9. ช่อง Width แสดงความกว้างตอนนี้ (รูปแบบเดียวกับ HUD) Enter = แบ่งครึ่ง 60 รอบบน log2(zoom) ด้วย `sensorViewGroundWidthM` (`sensorViewZoomForGroundWidth` ใน `sensorGeometry.ts`) จากความสูงและ Cone Half Angle ใน HUD ตอนนั้น ตัดให้อยู่ใน [1, 262144] ; พิมพ์ผิด = ช่องกลับเป็นค่าเดิม + คำแนะนำไทยข้างช่อง (`role=status` ไม่ลง Message Viewer) ; ไม่มีตำแหน่ง = ข้อความไทยอีกข้อ ; Escape หรือออกจากช่อง = ทิ้งที่พิมพ์ — ความสูงของดาวเปลี่ยนตามเวลา ความกว้างจึงคงที่แค่ ณ เวลาที่กด Enter
10. e2e: กดปุ่ม 26 ครั้งถึง ×8192 (ทุกครั้งที่สองตรวจป้ายเลขยกกำลังสองตามเดิม) ปุ่ม Zoom In ที่ ×8192 ยังกดได้ (ปลายใหม่คือ ×262144: assertion เดิม "ปิดใช้ที่ปลาย" กลับข้าง) ล้อหนึ่งรอยจาก ×4 ได้ ×2.8 และเพิ่มการตรวจช่อง Width "1.5 km" ด้วยสูตรอิสระ 2·h·tan(fov/2) คลาดไม่เกิน 3%
11. ชั้นทึบที่โหลดชิ้นไม่ได้ไม่บังชั้นข้างใต้: ชิ้นพลาดเกินเกณฑ์ `tilesFailing` (ได้ผล ≥ 8 ชิ้น พลาด ≥ 75% เกณฑ์เดียวกับ HUD และ ion) ใน viewer นั้น = ชั้นนั้นไม่นับเป็นทึบ แล้ว sync ทางไมโครทาสก์ (ไม่แก้รายการชั้นกลาง errorEvent) ชั้นข้างใต้ลงไปถึงชั้นทึบถัดไปจึงถูกสร้าง ล้มซ้อนกันได้ทีละชั้น (OSM ล้ม → Sentinel-2 ถูกสร้าง ถ้า Sentinel-2 ล้มด้วย → Blue Marble ตามมา) ค้างไว้ต่อ (id, token) จนชั้นถูกเอาออก (ปิดแล้วเปิดสวิตช์/Show) token เปลี่ยน หรือแผนของ ion เปลี่ยน — OSM ถูกบล็อก/เน็ตหลุด หรือ EOX หยุด/ไม่ว่าง เดิมเหลือแต่ Natural Earth II — ค้างแบบ "ไม่กลับมาทึบเอง" กันการสลับชั้นไปมาเมื่อเน็ตกระตุก: เน็ตกลับมาแล้วชั้นข้างใต้ที่ถูกสร้างไปยังโหลดอยู่ (คำขอเกินจำเป็นจนผู้ใช้ปิดแล้วเปิดชั้นนั้น)
12. proxy ของสภาพแวดล้อม: ตัวส่ง keep-alive เชื่อมตรง จึงเดิมไม่สน `HTTPS_PROXY` / `https_proxy` ที่ opener ของ urllib เคยใช้ — คำขอที่ `urllib.request.getproxies()` มี `https` และ `proxy_bypass(host)` ไม่ยกเว้น ไปทาง `build_opener(NoRedirect)` เดิม (หลังตรวจ host/พอร์ต/userinfo แล้ว; test ที่ฉีด connection factory ไม่ต่อ opener จริง) — ผู้ใช้หลัง proxy องค์กรไม่ควรถูกข้าม proxy เงียบ ๆ — คำขอผ่าน proxy ไม่ได้ connection ซ้ำ (ช้ากว่าแต่ถูกต้องเหมือนเดิม)
13. ถ้อยคำ keep-alive: "ไม่มีคำขอใดถึงปลายทางสองครั้ง" แก้เป็น GET หนึ่งคำขอส่งซ้ำได้อย่างมากหนึ่งครั้ง และเฉพาะเมื่อ connection ว่างถูกตัดก่อนตอบ (`keepalive.py`, `imagery.py`) — ประโยคเดิมแรงเกินจริง: ปลายทางที่ตัด connection ระหว่างรับคำขออาจเห็นคำขอแรกแล้วเราส่งซ้ำ — ไม่มี (แก้ถ้อยคำ)
14. ช่อง Width บอกเมื่อค่าเกินช่วง: ตั้งเป็น ×262144 หรือ ×1 ให้ตามเดิม แต่แสดงคำแนะนำไทยที่บอกความกว้างแคบสุด/กว้างสุดที่ความสูงตอนนี้ตั้งได้ (`sensorViewGroundWidthRangeM`, `sensorView.widthClamped`) คำแนะนำของช่องนี้ผูกกับ zoom ตอนแสดง: ซูมเปลี่ยนด้วยปุ่มหรือล้อ = หาย — การบีบเงียบทำให้ผู้ใช้ไม่รู้ว่าค่าที่พิมพ์ไม่ได้ผล และคำแนะนำค้างเมื่อซูมไปทางอื่นทำให้เข้าใจผิด — ช่วงคิดจาก Cone Half Angle และความสูง ณ เวลาที่กด Enter ความสูงเปลี่ยนตามเวลาจึงเป็นค่าประมาณ ณ ตอนนั้น

### การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. (Task 1) URL ของโมเดลเป็น path ของ glb ที่ catalog ระบุ (`/models/<glb ใน catalog>`) ไม่ประกอบจาก id — โมเดล `galileo-foc` เป็นไฟล์ `galileo_foc.glb` ไม่ใช่ `galileo-foc.glb` ซึ่งทำให้ข้อกำหนด `/models/<id>/<id>.glb` ในแผนผิดสำหรับตัวเดียวนี้ (แก้ข้อกำหนดของแผน ไม่ใช่ไฟล์ของ models) — ไม่มี
2. (Task 2) ฟังก์ชันเฟรมคืน `null` เมื่อ `bodyFrame` ของ sensor เป็น `null` (ตำแหน่งและความเร็วหาเฟรมไม่ได้) และ result เป็นอาร์กิวเมนต์ที่ไม่บังคับ; ตำแหน่งดวงอาทิตย์ใช้ตัวเดียวกับแสงของหน้าต่าง 3D (คลาดจาก almanac 0.37° เพราะ precession ก่อน ICRF) — สอดคล้องกับสิ่งที่วาดอยู่ ไม่ใช่ตำแหน่งที่แม่นที่สุด — ไม่มี
3. (Task 3) แก้ yaw ของโมเดลด้วย `entity.orientation = q(body→ECEF) · R_z(−90°)` (ค่าตั้งต้น glTF 2.0 ของ Cesium: up Y, forward Z) — `ModelGraphics` ไม่มี upAxis/forwardAxis ค่าตั้งต้นทำให้ nadir (+Z) ถูกอยู่แล้วแต่ yaw คลาด 90° พิสูจน์กับ `ModelUtility.getAxisCorrectionMatrix` จริง (คลาด < 1e-6°) และตรวจซอร์ส Cesium ว่า ModelVisualizer ไม่ส่งแกน — ถ้า Cesium รุ่นใหม่เปลี่ยนค่าตั้งต้น test ที่อ่านซอร์สล้มทันที ไม่ใช่โมเดลหันผิดเงียบ ๆ
4. (Task 3) แผงโซลาร์หมุนด้วย `fromAxisAngle(−UNIT_Z, θ)` ในพื้นที่ node ของ glTF ดิบ — ทุก wing node ของทั้ง 23 โมเดลมีแค่ translation และแขวนกับ root ที่ไม่มี transform แกน local จึงเป็นแกน glTF ดิบ และ +Y ของตัวดาวคือ −Z ของ glTF ตรวจกับ glb จริงทุกโมเดลและกับมุม θ หลายค่า — ถ้า glb ชุดใหม่ใส่ rotation ให้ node แผง แกนจะผิด (มี test ตรวจโครงสร้างทุกโมเดลใน catalog)
5. (Task 3) normal ด้านเซลล์ตอนมุมศูนย์ของแผง: −X สำหรับ GNSS ทุกตัว, `generic` และ `himawari-9`; +Z สำหรับ `terra` และ `goes`; ค่าตั้งต้น +X สำหรับ `aqua` และ `suomi-npp` (ไม่แน่นอน) — อ่านจากทิศหน้าสามเหลี่ยม (area-weighted) ของวัสดุเซลล์ใน glb จริง ตรงกับ NOTES ของ gps-iif, gps-iii, galileo-foc (−X) `terra` แผงเป็นสองชั้นหันหลังชนกัน เซลล์ทั้งสองหน้า (แกนแน่นอน ด้านเป็นไปตามอำเภอใจ) `goes` ความเชื่อมั่นปานกลาง `aqua` และ `suomi-npp` ทั้งสองหน้าใช้พื้นผิวเดียวกัน (`tex_01`) ตัดสินด้านเซลล์ไม่ได้ ค่า +X อย่างน้อยทำให้แผงหันหาดวงอาทิตย์ — ด้านที่เห็นอาจเป็นด้านหลังของ `aqua` และ `suomi-npp` และ `terra` ใช้แกนจากเมช (±Z) แทน "+X ตั้งต้น" ของ brief เพราะ +X จะทำให้แผงตะแคงขอบเข้าหาดวงอาทิตย์
6. (Task 3) ไฟล์ glb ถูก fetch ครั้งเดียวต่อ URL ตรวจหัวไฟล์ (`glTF` เวอร์ชัน 2) แล้วให้ Cesium โหลดจาก `blob:` URL ของ origin เดียวกัน — server ตอบ path ที่ไม่มีไฟล์ด้วย SPA fallback เป็น `200 text/html` และ `ModelVisualizer` แค่ `console.log` เมื่อโหลดไม่สำเร็จ ไม่มีทางให้โค้ดเราแจ้งได้ หากไม่ตรวจเอง จุดจะถูกซ่อนแล้วดาวหายไป วิธีนี้ยังรับประกัน request หนึ่งครั้งต่อโมเดลข้ามทุก entity และทุกหน้าต่าง — ใช้หน่วยความจำ blob ราว 1 MB ต่อโมเดลที่ใช้จริงตลอดอายุหน้า (ไม่ revoke) และ glb ที่หัวถูกแต่ Cesium ถอดรหัสไม่ได้ภายหลังยังตรวจไม่ได้ (ดาวนั้นมองไม่เห็นแต่ยังคลิก มีป้ายชื่อและสีได้)
7. (Task 4) ตัวกัน request นอกเครื่องของ e2e (`fixtures.ts`) ไม่แก้: อนุญาต `blob:` และ `data:` อยู่แล้ว การโหลดโมเดลจาก `blob:` ของ origin เดียวกันจึงผ่าน และนับ request ที่ไป `/models/catalog.json` (ต้องครั้งเดียว) กับ `/models/<...>.glb` (ไม่เกินครั้งเดียวต่อไฟล์) แยกใน `models.spec.ts` — ไม่ขยายกติกาของตัวกันให้ spec เดียว — ไม่มี
8. (Task 4) "ดาวที่แสดง" ใน e2e = ดาวใน scenario ที่ `labelShown` เป็นจริงในหน้าต่าง 3D ตัวแรก (data ของ e2e มีดาวชุดเล็กและมีดาวที่ถูกตัวกรองดาวซ่อน) และ `modelCount()` ต้องเท่านั้นพอดี — ไม่ผูกกับรายชื่อดาวตายตัวใน test — ถ้าป้ายถูกปิดแยกจากการแสดงดาว จำนวนจะไม่ตรงและ test ล้ม (ไม่ใช่ผ่านผิด)
9. (Task 4) ตรวจท่าทางด้วย test hook ที่อ่านค่าจริงจาก entity (`satelliteOrientation(ชื่อดาว)`: แกน +X, +Y, +Z ของตัวดาวใน ECEF โดยถอด `MODEL_AXIS_FIX` ออกจาก `entity.orientation`) ไม่ใช้ภาพจับหน้าจอ และ `pointShown(ชื่อดาว)` บอกว่าจุดของดาวแสดงอยู่ไหม — เกณฑ์ +Z ชี้ศูนย์กลางโลกคลาด ≤ 0.5° (ที่ 26,560 km ดาวเคลื่อนไปราว 0.008° ต่อวินาที ค่านี้จึงกว้างพอสำหรับรอบ throttle 250 ms) — hook อ่านผลลัพธ์ของโค้ดเดียวกับที่วาด การแปลงแกนของ glb พิสูจน์แยกใน unit test กับ Cesium จริง e2e จึงตรวจว่า pipeline ทำงานบน scene จริง ไม่ได้พิสูจน์แกนซ้ำ

### เรื่องที่ผู้ใช้ควรรู้

- **ไม่มี noon/midnight turn**: yaw steering ใช้แบบ nominal ทุกช่วง ตอนมุม β ต่ำ ดาวจริงหมุนต่างจากโมเดล
- **BeiDou ไม่จำลองโหมด orbit-normal**: ใช้ yaw steering แบบ nominal ทุกช่วง (รวม BeiDou GEO และ IGSO)
- **ด้านเซลล์ของ `aqua` และ `suomi-npp` ไม่แน่นอน**: แผงหันหาดวงอาทิตย์แต่ด้านที่เห็นอาจเป็นด้านหลัง; `goes` ปานกลาง
- **แพ็กเกจใหญ่ขึ้นราว 19 MB**: `dist/models` = 19.4 MB (23 glb และ catalog) `dist` ทั้งหมดจากราว 14 MB เป็นราว 33 MB ไม่ส่ง `_refs/` (ภาพอ้างอิงราว 55 MB) และอะไรนอก catalog
- หน้าต่าง 2D ยังเป็นจุด; Sensor View ใช้ค่าตั้งต้นของโมเดล (เปิด, 48 พิกเซล, 30,000 km) และซ่อนโมเดลของดาวแม่ที่กล้องติดอยู่; View From/To ที่ From เป็นดาวซ่อนโมเดล จุด และป้ายของดาวนั้น;
- ดาวที่ห่างกล้องเกิน Model Detail Threshold (ค่าตั้งต้น 30,000 km) เป็นจุดแบบเดิม ซูมเข้าใกล้หรือเพิ่มค่านี้ (หน้า Details) เพื่อเห็นโมเดลของดาวไกล; ไม่มีตัวเลือกโมเดลต่อดาว (Properties ของดาวไม่มีหน้า 3D Graphics - Model) และไม่มี override ตาม COSPAR (`overrides` ใน catalog ว่าง)
- ปิด Satellite Models ที่ 3D Graphics Window Properties หน้า Details (เปิดแถบ 3D Window Defaults จาก View → Toolbars ก่อน) จะกลับเป็นจุดทันที

1. ท่าทางตอนเริ่ม/จบ animation: `updateModelAttitudes` ข้ามดาวที่ไม่มีตำแหน่ง t − 1 s หรือ t + 1 s ตัวอย่างแรกและตัวสุดท้ายจึงได้ quaternion เอกลักษณ์ (yaw และ nadir ผิด) จนกว่านาฬิกาจะเดิน ตอนนี้ใช้ `sensorDraw.velocityOf` ตัวเดียวกับ sensor (ผลต่างข้างเดียว 1 s ที่ขอบช่วง เพิ่มอาร์กิวเมนต์ result ไม่สร้าง object ใหม่ต่อดวง) ข้ามเฉพาะเมื่อไม่มีทั้งสองข้าง unit test ที่ตัวอย่างแรกและตัวสุดท้าย และ e2e ตรวจท่าทาง ณ เวลาเริ่มของ scenario
2. restyle ตอน glb ทยอยมา: เดิมรวบแค่ภายใน microtask เดียว (ราว 17 ครั้งตอนเปิดหน้า) ตอนนี้ `SatModelSource` เปิดชุด `MODEL_BATCH_MS` = 100 ms ที่ไฟล์แรกเสร็จ ไฟล์ที่เสร็จในชุดเดียวกัน = `changed()` (restyle) ครั้งเดียว ไฟล์ที่มาทีหลังเปิดชุดใหม่ — ดาวเป็นจุดนานขึ้นไม่เกิน 100 ms
3. glb ที่ Cesium โหลดไม่ได้: (ก) `glbProblem` ตรวจทั้งไฟล์ก่อนทำ blob URL — ความยาวในหัว, JSON chunk อ่านได้, `asset.version` = "2.0", `extensionsRequired` มีแต่ชื่อที่ Cesium รองรับ (รายการคัดจาก `ModelUtility.supportedExtensions` และ test เทียบกับของ Cesium ที่ติดตั้ง), chunk พอดีไฟล์ (ข) `watchModelErrors` ฟัง `errorEvent` ของ primitive โมเดลดาว (หาใน `scene.primitives` ทุก `preRender` ก่อนเฟรมที่ update มัน ไม่นับ TextureError) โมเดลนั้นถือว่าล้มเหลวทั้งหน้าเว็บ ข้อความไทย `MODEL_LOAD` ครั้งเดียวต่อ id และทุกหน้าต่าง restyle ดาวของโมเดลนั้นกลับเป็นจุด — ปิดข้อเสียในการตัดสินใจข้อ 6 (ความล้มเหลวที่ `Model.fromGltfAsync` ปฏิเสธโดยไม่มี primitive ยังมองไม่เห็นจากภายนอก แต่สิ่งที่ Cesium ตรวจในขั้นนั้นถูกตรวจใน (ก) แล้ว)
4. ความสะอาดของ test: `tests/unit/setup.ts` ตอบ fetch ที่ไม่ได้ stub ไป `/models/...` ด้วย promise ที่ไม่มีวันเสร็จ (ไม่ออกเครือข่าย ดาวเป็นจุด) ข้อความเตือน `MODEL_CATALOG` ใน test ของหน้าต่าง 3D ที่ mount จริงหายไป และ `sat-model-render.test.ts` ใช้ `vi.spyOn(URL, "createObjectURL")` พร้อม `vi.restoreAllMocks()` แทนการแก้ `URL` ทั้งตัว

### รอบแก้ 2 (หลัง final review และการดูด้วยตาของ controller: โมเดล 120 ตัวขึ้นครบ แต่แต่ละตัวเป็นเศษสีเข้มราว 10 พิกเซลบนพื้นอวกาศดำ เห็นยากกว่าจุดสีเดิม)

1. ไม่ตั้ง `maximumScale` ของโมเดล (เดิม 20000) — `Model.updateComputedScale` ของ Cesium 1.147 ขยายเป็น `minimumPixelSize × เมตรต่อพิกเซล / (2 × รัศมีโมเดล)` แล้วจำกัดด้วย `maximumScale` ถ้ามี โมเดลยาว 17 m จึงได้ 48 พิกเซลถึงราว 6,000 km เท่านั้น ขณะที่ดาว GNSS ห่างกล้อง Home View 10,000–60,000 km; ค่าจำกัดใด ๆ ก็หมดผลเกินระยะหนึ่ง (ระยะ ∝ ค่าจำกัด × รัศมี / พิกเซล) ไม่จำกัดจึงได้ Model Pixel Size ทุกระยะ test คำนวณด้วยสูตรของ Cesium (อ่านซอร์สยืนยันสูตร + `frustum.getPixelDimensions` จริง) ที่ 50,000 และ 80,000 km, fov 60°, 1000 พิกเซล, รัศมี 0.5–30 m, 16–256 พิกเซล — ถ้าผิด: โมเดล 256 พิกเซลที่ระยะไกลมากมีขนาดจริงหลายหมื่น km ในฉาก อาจตัดกับโลกในภาพ (เลือกได้เอง: Model Pixel Size และ Model Detail Threshold)
2. ขอบ (silhouette) สีของระบบ 1.5 พิกเซลทุกโมเดล ดวงที่เลือก 3 พิกเซล; สีของระบบผสม 50% (เดิม 30%); `lightColor` = ขาว × 2 (ค่าตั้งต้นของ `SunLight` ใน Cesium; หน้าต่างตั้ง `scene.light.intensity` = Sun Level/100 = 1 ซึ่งทำให้โมเดลมืดครึ่งหนึ่ง); `imageBasedLightingFactor` (1, 1) และ `environmentMapOptions.enabled = false` — environment map แบบ dynamic คำนวณจากบรรยากาศที่ตำแหน่งโมเดล ในอวกาศเกือบดำ (ด้านกลางคืนดำสนิท) และสร้างใหม่ทุกครั้งที่โมเดลเคลื่อนเกิน 1 km (`maximumPositionEpsilon`: ทุกเฟรมของ animation ทุกดวง) ปิดแล้ว Cesium ใช้ spherical harmonics ค่าคงที่ (`DEFAULT_SPHERICAL_HARMONIC_COEFFICIENTS`) = แสงรอบตัวเท่ากันทุกทิศ — ถ้าผิด: ด้านสว่างอาจจ้าไป หรือแสงรอบตัวยังน้อยไป (controller ตรวจด้วยตา ปรับได้ที่ค่าคงที่ใน `satModelGraphics.ts`) และ Sun Level ไม่มีผลกับโมเดลอีก
3. Model Detail Threshold (km, ค่าตั้งต้น 30,000, จำนวนเต็ม 1,000–200,000) ในหน้า Details ป้าย `ours()` เพราะ STK reference ไม่มีคำว่า detail threshold — รอบ throttle 250 ms เดียวกับท่าทาง (`applyModelDetail` ก่อน `updateModelAttitudes`) ดาวที่แสดงอยู่และห่างกล้องน้อยกว่าค่านี้เป็นโมเดล ไกลกว่าเป็นจุดเดิม (`model.show = false`: ไม่มี draw call ไม่คำนวณท่าทาง) กล้องขยับ: `camera.percentageChanged = 0.05` + `camera.changed` ขอรอบ throttle; ดาวที่ซ่อน (ธง, Show, โหมด Camera ของ Sensor View) ไม่ถูกแตะ — แบบ STK และลด draw call (final review ประมาณ 6,000–7,000 draw call เมื่อทั้ง 146 ดวงเป็นโมเดล) ดาวไกลกลับเป็นจุดสีที่ผู้ใช้เห็นชัดกว่า — ถ้าผิด: ค่าตั้งต้นที่ Home View ทำให้บางดวงเป็นจุดบางดวงเป็นโมเดล (ตั้งใจ) e2e ที่นับโมเดลจึงตั้ง 200,000 km ก่อน
4. View From/To ที่ From เป็นดาว: ซ่อนโมเดล จุด และป้ายของดาว From แบบเดียวกับดาวแม่ของ Sensor View (`cameraSatellite` + `hideCameraSatellite`) restyle ตอนเข้าและออก รอบ Model Detail Threshold ไม่แตะดาวนี้ (exclude) From เป็น Facility ไม่ซ่อนอะไร — วัสดุทุกชิ้นของโมเดลเป็น doubleSided กล้องที่อยู่ในตัวโมเดลเห็นแต่ผนังด้านใน — ถ้าผิด: มองไม่เห็นดาว From เองระหว่าง View From/To (ซึ่งกล้องอยู่ในตัวมันอยู่แล้ว)
5. test hook `flyToSatellite(ชื่อดาว, rangeM)` (เฉพาะ `?test`): ปล่อยกล้องจากการตาม object/View From/To แล้ว `camera.lookAt(ดาว, offset ENU)` ที่ offset = rangeM ไปทางดวงอาทิตย์ (เห็นด้านสว่าง) แล้ว `lookAtTransform(IDENTITY)` คืนกรอบโลก และขอรอบโมเดลทันที — ให้ controller ดูโมเดลด้วยตาบน GPU จริงได้โดยไม่ต้องลากกล้อง unit test ตรวจคณิต (offset ENU กลับเป็น ECEF ขนานกับทิศดวงอาทิตย์) และกล้องในหน้าต่างที่ mount; e2e ใช้คู่กับ threshold 1,000 km — ไม่มี
6. สาเหตุที่ e2e สะดุด: `sceneLoadedAt` ยังอ่านได้จากหน้าต่าง 3D ที่การจัดหน้าต่างตาม workbook กำลังจะแทน (ราว 1.2 วินาทีต่อมา) — `useLayout.restoredAt` = เวลาที่ `restoreFor` ครั้งล่าสุดจัดหน้าต่างเสร็จ (null ระหว่างรอ, ครั้งที่ถูกแซงไม่ตั้ง) test hook `workbookRestoredAt()`; e2e `openScenario` รอค่านี้ และ `waitForScene` รอ `sceneLoadedAt ≥ workbookRestoredAt` (หน้าต่างที่ workbook สร้างโหลดเสร็จหลังการจัดหน้าต่างเสมอ) — ถ้าผิด: workbook ที่ไม่มีหน้าต่าง 3D ทำให้ `waitForScene` รอจนหมดเวลา (เหมือนเดิม)

### การตัดสินใจ (Ruling — เหตุผล — ถ้าผิดเสียอะไร)

1. **กฎทุกตัวไม่มีสถานะ** ψ ณ t เป็นฟังก์ชันของ (β, μ, μ̇, |r|) ณ t เท่านั้น; `updateModelAttitudes` เลิกใช้ `prevEy` — การเลื่อนเวลา รอบ throttle 250 ms และการเล่นต่อเนื่องได้ท่าทางเดียวกันที่เวลาเดียวกัน (test: อัปเดตทุก 250 ms 10 นาที เทียบกับอัปเดตครั้งเดียวหลังกระโดดเวลา ได้ quaternion เท่ากันตรงตัว) — ถ้าผิด: กฎที่ต้องการประวัติจริง (SECM postponed flip, Γ ของ IOV ณ จุดเข้ากล่อง, t_init ของ FOC เมื่อ β เปลี่ยนระหว่างการหมุน) ได้ค่าประมาณจากเรขาคณิตปัจจุบันแทน
2. **การหมุนจำกัดอัตราเป็นแบบกึ่งกลาง node** (IIR, IIF noon, GLO-M noon, GLO-K, QZSS-2): ψ = ψ_node + sign(dev) · min(|dev|, R|x|/μ̇) โดย ψ_node = −90° sign β, dev = wrap(ψ_nom − ψ_node) — ตามคำว่า "centered" ของตาราง §3.1 (ไม่ใช่ §4.2 ซึ่งแก้ |ψ̇_nom(μ_s)| = R = จุดเริ่มของ Kouba) คงขีดจำกัดอัตราและความต่อเนื่อง ได้รูปปิดไม่ต้องหาจุดตัดเชิงตัวเลข ต่อเนื่องที่ปลายทั้งสอง |ψ̇| = R พอดีระหว่างหมุน และเป็น nominal เองเมื่อ |β| ≥ atan(μ̇/R) — ความต่างที่รู้: สูตร Kouba ใน §3.2 / §4.2 (เริ่มที่ |ψ̇_nom(μ_s)| = R แล้ววิ่งจนทัน) ไม่สมมาตร ที่ node ψ ของเราผ่าน ±90° ขณะที่ของ Kouba ยังตามหลังอยู่ (β = 0.5° ต่างกันราว 40° ที่ node)
3. **GPS IIF β-bias**: β ∈ [−0.7°, 0) หมุนเที่ยงวันทางยาวผ่าน +90° sign β ด้วยสูตรเดียวกัน (|dev| = 180° − |dev ปกติ|) ตาม §3.3 ข้อ 2 และ §4.3 ข้อ 3 — ถ้าผิด: ดาว IIF ในช่วงนี้หันกลับด้านระหว่าง noon turn
4. **เงาโลกทรงกระบอก** (`inEarthShadow`: r · ŝ < 0 และ |r × ŝ| < R⊕ = 6,378,137 m) ใช้ ŝ จากดาว ซึ่งเท่ากับ |μ| < μ_e = acos(cos θ0 / cos β), θ0 = asin(R⊕/|r|) พอดี; IIF ในเงา = อัตราคงที่จาก ψ_nom(−μ_e) ถึง ψ_nom(μ_e); GLO-M = หมุน 0.25°/s จากจุดเข้าเงาแล้วค้าง ψ_nom(μ_e) — จุดเข้าเงาหาเชิงวิเคราะห์ ไม่จำว่าเข้าเงาเมื่อไร — ถ้าผิด: เงาจริงเป็นกรวย (penumbra) ขอบเงาคลาดไม่กี่นาที
5. **β, μ ใช้ทิศดวงอาทิตย์จากดาว** (เหมือน `yawSteeringFrame` เดิม) ไม่ใช่จากศูนย์กลางโลก — `nominal_ys` จึงให้เฟรมเดียวกับของเดิมนอกจุดเอกฐาน (test < 1e-9) ต่างจากแบบศูนย์กลางโลกไม่เกิน R/AU ≈ 0.016° — ไม่มี
6. **Galileo FOC**: t_init = จุดที่ ε ลดถึง 10° (x_i = acos(cos 10° / cos β) จาก node) และครึ่งคาบ cosine = ช่วงสมมาตร 2x_i/μ̇ แทน 2828 s คงที่ — ความยาวการหมุนของ Galileo 2816 s ที่ β = 0, 2759 s ที่ 2°, 2583 s ที่ 4° (สั้นกว่า 2828 s ได้ถึงราว 9% อัตราสูงสุดจึงสูงกว่าแบบตามตัวอักษรราว 9%) ส่วนสูตร GSC ตามตัวอักษรกระโดดตอนกลับเข้า nominal ราว 2.5° ที่ β = 4° — ถ้าผิด: การหมุนสั้น/เร็วกว่าของจริงได้ถึงราว 9% ที่ |β| ใกล้ 4.1°
7. **Galileo IOV**: Γ = sign(S_oy) ปัจจุบัน (β คงที่ตลอดการผ่านกล่องจึงเท่ากับค่า ณ จุดเข้า) — ไม่มี
8. **CAST/SECM**: CAST ใช้ β หน่วง (d = 80,000, β0 = 3° ทั้ง MEO และ IGSO ไม่ใช้ 2.8° ของ MEO และไม่ใช้แบบ WHU); SECM ใช้สเปก CSNO (β = ±3°) ไม่จำลองการพลิกที่เลื่อนออกไป (ต้องมีประวัติ); BDS-2I/2M ทุกดวง YS ↔ ON ที่ 4° (ไม่มีรายการ PRN ที่อัปเกรดเป็น CYS) — ถ้าผิด: C06/C13/C14/C16 ช่วง β ต่ำแสดง ON ขณะที่ดาวจริงใช้ CYS
9. **QZSS-2**: ψ_1 = −90° sign β ทั้งที่เที่ยงคืนและเที่ยงวัน (ψ_nom(μ = 180°) = atan2(−tan β, 0) = −90° sign β; หมายเหตุใน §3.8 ที่ว่า "reversing at noon" ตรงกับทิศหมุน ไม่ใช่ ψ_1) — ไม่มี
10. **ez = nadir ทุกกฎ ยกเว้น NavIC** (รอบแก้: ข้อจำกัด "ราว 1°" เดิมผิด review วัดได้ 7.0–7.4° ที่ GEO 32.5°E/129.5°E และ 5.8–6.7° ที่ IGSO) NavIC ทำตาม §4.3 ข้อ 4: ez = unit(r_tgt − r) โดยเป้า (5°N, 83°E, 0 m) บน WGS84 แล้วฐาน ON รอบแกนนั้น (y0 = −h ฉายให้ตั้งฉากกับ ez, x0 = y0 × ez) YS = ψ ที่ทำให้ดวงอาทิตย์อยู่ในระนาบ X-Z ฝั่ง +X (เท่ากับ ey = unit(ez × ŝ)), ON (|β| < 4° ของกรอบภูมิศาสตร์) = ψ = 0 ไม่มีสถานะ test: มุมระหว่าง ez กับทิศไปเป้า < 0.01° — ถ้าผิด: ไม่มี (สเปกกำหนด) นอกจากเกณฑ์ ON ที่ยังเป็นค่าประมาณ
11. **กฎต่อดาว ไม่ใช่ต่อโมเดล**: `SatModelSource.specFor` เลือกกฎจาก block ของดาว (`attitudeLawFor(block, eo)`) spec ต่อ (โมเดล, กฎ) — BDS-2G กับ BDS-2I ใช้ glb เดียวกันแต่กฎต่างกัน; ดาวที่ตกไป `generic` (BDS-3SI-CAST/SECM) ยังได้กฎของ block ตัวเอง; ดาวสำรวจโลก = `nadir_velocity`; block ที่ไม่รู้จัก = `nominal_ys` — ไม่มี
12. **`cell_normal` จาก catalog**: `cellNormalOf` อ่านเฉพาะ "+X", "-X", "+Z", "-Z" ตรงตัว (รอบแก้: ±Y ตัวพิมพ์เล็กหรือค่าอื่น = ตารางสำรอง + ข้อความไทย `MODEL_CELL_NORMAL` ใน Message Viewer ครั้งเดียวต่อโมเดล) (terra −Z, suomi-npp −X, aqua +X, goes +Z, ตัวอื่น −X) ไม่มีฟิลด์หรือค่าอ่านไม่ได้ = ตารางสำรอง `WING_ZERO_NORMAL` ซึ่งปรับให้ตรงกับ catalog (terra เดิม +Z, suomi-npp เดิม +X ตั้งต้น) และค่าตั้งต้นของตารางเป็น −X — ถ้าผิด: แผงของ terra และ suomi-npp หันด้านหลังเข้าหาดวงอาทิตย์ (แกนแผงยังถูก)
