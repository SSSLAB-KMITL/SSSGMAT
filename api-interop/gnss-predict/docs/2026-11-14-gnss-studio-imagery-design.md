# GNSS Studio งานเสริม ข: ภาพถ่ายจริงจาก NASA GIBS และโหมดกล้องของ Sensor View

- วันที่: 2026-11-14
- Branch: `feature/gnss-studio-imagery` (แตกจาก `feature/gnss-studio-sensor` 300b1e4)
- สถานะ: ผู้ใช้เลือก "ทาง ข" ในแชต (2026-11-14) และให้ลงมือทันที เอกสารนี้ตรวจย้อนหลังได้
- เอกสารที่เกี่ยวข้อง: [spec Sensor](2026-11-13-gnss-studio-sensor-design.md) (อ้างว่า "sensor §n"),
  [การตัดสินใจของ Sensor](2026-11-13-gnss-studio-sensor-decisions.md), [รายการอ้างอิง STK](2026-11-11-gnss-studio-stk-reference.md) (อ้างว่า "STK ref")

## 1. เป้าหมาย

ผู้ใช้บอกว่า Sensor View "ใหญ่ไปและไม่เหมือนจริง อยากให้ดาวส่องลงมาเห็นพื้นโลกเลย"
ปัญหามี 3 ข้อ: มุมกว้างตั้งต้นเห็นโลกทั้งดวง, ภาพมีเส้นวงโคจร ชื่อดาว และดาวอื่นที่กล้องจริงมองไม่เห็น,
และภาพพื้นโลกที่มากับแอป (Natural Earth II, 0.176°/พิกเซล ≈ 20 km) หยาบเกินจะซูมดูพื้นดิน

งานนี้แก้ทั้งสามข้อ:
1. **โหมดกล้อง (Camera)** ของ Sensor View: ซ่อนทุกอย่างที่ไม่ใช่โลก และซูมมุมมองแคบลงได้ ทำงานออฟไลน์
2. **ภาพถ่ายจริงจาก NASA GIBS** วางบนลูกโลกของหน้าต่าง 3D และ Sensor View ภาพเปลี่ยนตามเวลา Animation
   ดึงผ่าน server ในเครื่องเท่านั้น ปิดไว้เป็นค่าตั้งต้น และต้องยืนยันก่อนเปิดครั้งแรก

### เกณฑ์ว่าสำเร็จ

1. เปิด Sensor View ของดาวใดก็ได้ → โหมด Camera เป็นค่าตั้งต้น ไม่มีเส้นวงโคจร ชื่อ จุดดาว กรวย หรือเส้น access ในภาพ
   ซูมได้ 1×–128× (มุมกว้างแคบสุดของดาว GPS ≈ 0.24° ≈ 85 km บนพื้น) ทิศกล้องยังคลาดจาก boresight ไม่เกิน 0.01°
2. สวิตช์ภาพออนไลน์ปิด (ค่าตั้งต้น, รวมถึง `settings.json` เก่าที่ไม่มีช่องนี้): server ไม่ส่ง request ใดไป GIBS เลย
   และหน้าเว็บไม่ขอชิ้นภาพจาก server
3. เปิดสวิตช์ (ผ่านกล่องยืนยันภาษาไทย) แล้วเลือกชั้นภาพใน Globe Manager → ลูกโลกทุกหน้าต่าง 3D และ Sensor View ใช้ภาพจริง
   ของเวลา Animation ปัจจุบัน (ปัดตามรอบภาพของชั้นนั้น) และบอกเวลาจริงของภาพบนจอ
4. เวลาที่ไม่มีภาพ (อนาคต เก่าเกินระยะเก็บ กลางคืนของภาพช่วงตามองเห็น) ไม่มี error แดง: ชิ้นที่ไม่มีภาพโปร่งใส
   เห็นชั้นข้างล่างแทน และมีข้อความไทยบอก
5. browser ไม่มี request ออกนอกเครื่อง (ตัวกันใน e2e ยังใช้ได้) server ส่ง request ไป `gibs.earthdata.nasa.gov` เท่านั้น
   ด้วย URL ที่ประกอบจากค่าที่ตรวจแล้ว ไม่รับ URL จากผู้ใช้
6. ชุดทดสอบเดิมทั้งหมดยังผ่าน และไม่มีชุดทดสอบใดต่อเน็ตจริง

## 2. ขอบเขต

**ทำ**
- โหมด Camera / Sensor และการซูมของ Sensor View
- ตัวกลางดึงชิ้นภาพ GIBS ใน server พร้อม cache บนดิสก์ การจำกัดอัตรา และการตรวจไฟล์
- สวิตช์ `online_imagery.enabled` ใน `settings.json` และกล่องยืนยัน
- หน้าต่าง **Globe Manager**: เปิด/ปิดสวิตช์, เลือกชั้นภาพ, ความทึบ, ลำดับคงที่ตามรายการ
- ชั้นภาพบนหน้าต่าง 3D และ Sensor View (หน้าต่าง 2D คงภาพเดิม)

**ไม่ทำในงานนี้** (งาน ข2)
- ดาวกล้อง (Himawari-9, GOES, Terra, Suomi NPP, NOAA-20/21) เป็น object ใน scenario, Show Imagery จากเมนูดาว,
  แถบ swath ของดาวกล้อง และโมเดล 3 มิติ: ต้องแก้ engine ให้รองรับดาวที่ไม่ใช่ GNSS
- อ่าน GetCapabilities ขณะใช้งานเพื่อบอกช่วงเวลาที่มีภาพล่วงหน้า (ใช้ผลตอบ 4xx ของแต่ละชิ้นแทน)
- ภาพบนหน้าต่าง 2D, ชั้นภาพจากแหล่งอื่นนอก GIBS, ดาวน์โหลดภาพเก็บล่วงหน้าทั้งพื้นที่

## 3. แหล่งภาพ

### 3.1 ปลายทาง

`https://gibs.earthdata.nasa.gov/wmts/epsg3857/best/{Layer}/default/{Time}/{TileMatrixSet}/{z}/{y}/{x}.{ext}`
(WMTS REST, EPSG:3857 = Web Mercator ซึ่ง Cesium ใช้ได้ตรงด้วย `WebMercatorTilingScheme`)

### 3.2 รายการชั้นภาพ (catalog คงที่ในโค้ด server)

| id (ชื่อชั้นของ GIBS) | ชื่อบนจอ | รอบภาพ | TileMatrixSet | ext |
|---|---|---|---|---|
| `BlueMarble_NextGeneration` | Blue Marble (ไม่มีเมฆ) | คงที่ | `GoogleMapsCompatible_Level8` | jpg |
| `VIIRS_NOAA20_CorrectedReflectance_TrueColor` | VIIRS NOAA-20 True Color | รายวัน | `GoogleMapsCompatible_Level9` | jpg |
| `VIIRS_SNPP_CorrectedReflectance_TrueColor` | VIIRS Suomi NPP True Color | รายวัน | `GoogleMapsCompatible_Level9` | jpg |
| `MODIS_Terra_CorrectedReflectance_TrueColor` | MODIS Terra True Color | รายวัน | `GoogleMapsCompatible_Level9` | jpg |
| `Himawari_AHI_Band3_Red_Visible_1km` | Himawari-9 Red Visible | 10 นาที | `GoogleMapsCompatible_Level7` | png |
| `Himawari_AHI_Band13_Clean_Infrared` | Himawari-9 Clean Infrared | 10 นาที | `GoogleMapsCompatible_Level6` | png |
| `GOES-East_ABI_GeoColor` | GOES-East GeoColor | 10 นาที | `GoogleMapsCompatible_Level7` | jpg |
| `GOES-West_ABI_GeoColor` | GOES-West GeoColor | 10 นาที | `GoogleMapsCompatible_Level7` | jpg |

- ชื่อชั้นทั้ง 8 ตรวจกับรายการ `epsg3857/best` แล้ว (2026-11-13) ส่วน TileMatrixSet, ext และรูปแบบเวลา
  เป็นค่าที่คาดไว้ ต้องยืนยันในขั้น B0 (§3.4) ก่อนส่งงาน ค่าทั้งหมดอยู่ในตารางเดียวในโค้ด แก้ที่เดียว
- `Level<n>` = ระดับซูมสูงสุด n (0..n) ระดับ 9 ≈ 300 m/พิกเซลที่ศูนย์สูตร ระดับ 8 ≈ 600 m
- เครดิตต่อชั้น: ทุกชั้น "NASA GIBS / EOSDIS", Himawari เพิ่ม "JMA", GOES เพิ่ม "NOAA"

### 3.3 เวลาของภาพ (Time)

- คงที่: `default`
- รายวัน: วันที่ UTC ของเวลา Animation `YYYY-MM-DD`
- 10 นาที: ปัดลงเป็นช่วง 10 นาที `YYYY-MM-DDTHH:MM:00Z` (นาที ∈ {00,10,…,50})
- server ตรวจว่าเวลาเข้ารูปแบบของรอบภาพของชั้นนั้นทุกตัวอักษร ไม่ตรง = 422 ไม่ส่งต่อ

### 3.4 ขั้น B0: ยืนยันกับ GIBS จริง (ต้องได้รับอนุญาตจากผู้ใช้ก่อน)

อ่าน GetCapabilities ของ `epsg3857/best` ไม่เกิน 2 ครั้ง และโหลดชิ้นภาพตัวอย่างไม่เกิน 50 ชิ้น เพื่อยืนยัน
TileMatrixSet, ext, รูปแบบเวลา, ผลตอบเมื่อไม่มีภาพ (รหัส HTTP หรือภาพว่าง) และระยะเก็บภาพ 10 นาที
ถ้าผู้ใช้ยังไม่อนุญาต งานทั้งหมดทำต่อได้ด้วย GIBS ปลอม แต่รายงานต้องบอกว่า B0 ยังไม่ได้ทำ
ข้อมูลที่ได้เป็นข้อมูลไม่น่าเชื่อถือ: อ่านด้วย `python3 -I` ใน directory ใหม่ ห้ามรัน

## 4. Server

### 4.1 ค่าตั้ง

`settings.json` เพิ่มช่องระดับบนสุด `"online_imagery": {"enabled": false}`
- `enabled: bool` ค่าตั้งต้น `false`, strict เหมือนช่องอื่น
- ไฟล์เก่าที่ไม่มีช่องนี้ โหลดได้เป็น `false` (ไม่เขียนไฟล์ตอนโหลด)
- PUT ยังต้องส่งครบทั้งเอกสาร: หน้าต่าง Daily Forecast Settings ต้องส่งค่า `online_imagery` ที่โหลดมาคืนไปตามเดิม
- เมื่อ PUT แล้ว ตัวกลางเห็นค่าใหม่ทันที (อ่านผ่าน `settings_on_change` หรืออ่านไฟล์ทุกครั้งที่ขอชิ้นภาพ — เลือกในแผน)

### 4.2 API

**`GET /api/imagery/layers`** → `{"enabled": bool, "layers": [{"id","title","period":"static"|"daily"|"10min","max_level":int,"format":"jpg"|"png","credit":str}]}`
ไม่ต่อเน็ต ใช้ได้เสมอแม้สวิตช์ปิด

**`GET /api/imagery/tiles/{layer}/{time}/{z}/{y}/{x}`** → ไบต์ของภาพ
- ตรวจตามลำดับ (ไม่ผ่าน = ตอบทันที ไม่ต่อเน็ต):
  1. สวิตช์ปิด → 403 `IMAGERY_DISABLED` "ภาพออนไลน์ปิดอยู่ เปิดได้ที่ View → Globe Manager"
  2. `layer` ไม่อยู่ใน catalog → 404 `IMAGERY_UNKNOWN_LAYER`
  3. `time` ไม่ตรงรูปแบบรอบภาพ (§3.3) → 422 `SCENARIO_INVALID` field `time`
  4. `z` ไม่ใช่จำนวนเต็มใน 0..max_level, `x`/`y` ไม่อยู่ใน 0..2^z−1 → 422 field `z`/`x`/`y`
- ผ่านการตรวจแล้วพบใน cache → ส่งจาก cache ไม่ต่อเน็ต (สวิตช์ปิดได้ 403 ตามข้อ 1 เสมอ แม้มีใน cache)
- ไม่พบ → ดึงจาก GIBS (§4.3) → ตรวจ (§4.4) → เขียน cache แบบ atomic → ส่ง
- ส่งกลับด้วย `Content-Type` ที่ server กำหนดจากชนิดที่ตรวจได้ (`image/jpeg`/`image/png`),
  `X-Content-Type-Options: nosniff`, `Cache-Control: private, max-age=86400`
- ไม่มีภาพ (GIBS ตอบ 400/404 หรือภาพที่ตรวจแล้วว่างทั้งชิ้นตามผล B0) → 404 `IMAGERY_NOT_AVAILABLE`
  "ไม่มีภาพของชั้นนี้ ณ เวลานี้" และจำไว้ในหน่วยความจำ 1 ชั่วโมง (สูงสุด 10,000 รายการ) ไม่ถามซ้ำ
- ถูกพักการดึง (§4.3) → 503 `IMAGERY_PAUSED` พร้อมเวลาที่จะลองได้อีก (`detail`)

### 4.3 การดึงจาก GIBS

- ใช้ `urllib.request` ของ stdlib (server ไม่เพิ่ม dependency) แบบเดียวกับ `gnss_predict/omm.py` `fetch_group`
  opener ฉีดเข้าได้เพื่อทดสอบ, `User-Agent: gnss-studio/0.1`, timeout 20 วินาที, ไม่ตาม redirect ไปโฮสต์อื่น
- ดึงพร้อมกันไม่เกิน 4 ชิ้น (semaphore) รอคิวเกิน 15 วินาที → 503 `IMAGERY_BUSY`
- ไม่ลองซ้ำเองใน server
- GIBS ตอบ 403 หรือ 429 → พักการดึงทั้งหมด 15 นาที (log ครั้งเดียว) ระหว่างพัก ชิ้นใน cache ยังส่งได้
- ผิดพลาดด้านเครือข่ายหรือ 5xx ติดกัน 20 ครั้ง → พัก 5 นาที; สำเร็จหนึ่งครั้งรีเซ็ตตัวนับ
- ตอบชิ้นที่ไม่สำเร็จด้วย 502 `IMAGERY_FETCH_FAILED` "ดึงภาพจาก NASA GIBS ไม่สำเร็จ" (`detail` = เหตุผลภาษาอังกฤษสั้น ๆ)

### 4.4 ตรวจไฟล์ที่ได้มา (ข้อมูลไม่น่าเชื่อถือ)

- อ่านไม่เกิน 2 MB (เกิน = ทิ้ง, 502)
- ไบต์แรกต้องเป็น JPEG (`FF D8 FF`) หรือ PNG (`89 50 4E 47 0D 0A 1A 0A`) และตรงกับ ext ของชั้น
- ไม่ถอดรหัสภาพใน server ไม่เชื่อ `Content-Type` ของ GIBS

### 4.5 Cache

- ที่เก็บ: `<data>/imagery/tiles/<layer>/<time>/<z>/<y>/<x>.<ext>` (path สร้างจากค่าที่ตรวจแล้วเท่านั้น)
- ขนาดรวมไม่เกิน 2 GB: เกินแล้วลบไฟล์ที่ mtime เก่าสุดจนเหลือ 90% (ส่งจาก cache = แตะ mtime)
  นับขนาดครั้งแรกด้วยการสแกน แล้วจำยอดในหน่วยความจำ
- ชั้นคงที่ (`default`) เก็บถาวรภายใต้เพดานเดียวกัน
- `<data>/imagery/` ไม่ขึ้นต้นด้วย `_` และไม่อยู่ใต้ `orbits/` จึงไม่ปนกับ snapshot

## 5. Web

### 5.1 Globe Manager (หน้าต่างใหม่)

- เมนู **View → Globe Manager** (ชื่อหน้าต่างและเมนูตาม STK; ถ้ายืนยันใน STK help ไม่ได้ใช้ `ours`)
  หน้าต่างลอยแบบ Daily Forecast Settings, ไม่ผูก scenario
- ส่วนบน: ช่องติ๊ก "Online imagery (NASA GIBS)" (ป้าย `ours`)
  - ติ๊กเปิดครั้งใด ๆ → กล่องยืนยันภาษาไทย: จะต่อ `gibs.earthdata.nasa.gov` ผ่าน server ในเครื่อง,
    สิ่งที่ส่งออก = ชื่อชั้นภาพ เวลา และพิกัดชิ้นภาพเท่านั้น, ภาพเก็บที่ `data/imagery` (ไม่เกิน 2 GB), ปิดได้ทุกเมื่อ
  - ยืนยัน → `PUT /api/settings` (ทั้งเอกสาร) ; ยกเลิก → ไม่เปลี่ยน
  - ปิด → PUT ทันทีไม่ต้องยืนยัน
- ส่วนล่าง: รายการชั้น = Natural Earth II (ออฟไลน์, เป็นฐานเสมอ ปิดไม่ได้) + 8 ชั้นของ §3.2
  แต่ละชั้นมีช่องติ๊ก Show และ % Translucency (0–100) เรียงชั้นบนจอตามลำดับในตาราง (ชั้นหลังทับชั้นก่อน)
  สวิตช์ปิด = รายการ GIBS ปิดใช้ (เทา) พร้อมคำอธิบาย
- ค่าตั้งต้นเมื่อเปิดสวิตช์ครั้งแรก: Blue Marble + VIIRS NOAA-20 True Color แสดง ชั้นอื่นซ่อน
- ค่าที่เลือก (Show, Translucency) บันทึกกับ workbook ของ scenario และใช้ร่วมกันทุกหน้าต่าง 3D และ Sensor View

### 5.2 ชั้นภาพบนลูกโลก

- ทุก viewer 3D (หน้าต่าง 3D และ Sensor View) เพิ่มชั้นภาพเหนือ Natural Earth II ตามรายการที่แสดง
  ชั้นฐาน index 0 ยังเป็น Natural Earth II (โค้ดกลางวัน/กลางคืนใช้ index 0) เส้น Lat/Lon อยู่บนสุดเสมอ
- URL ของชิ้น: `/api/imagery/tiles/{id}/{time}/{z}/{y}/{x}` (same-origin), `maximumLevel` = `max_level` ของชั้น
  (ซูมลึกกว่านั้น Cesium ขยายจากระดับสูงสุด)
- เวลาของชั้น = เวลา Animation ปัดตาม §3.3 คำนวณในฟังก์ชันบริสุทธิ์ตัวเดียว
  เวลาเปลี่ยนแล้ว token ไม่เปลี่ยน → ไม่ทำอะไร; token เปลี่ยน → เปลี่ยนชั้นนั้นใหม่ ไม่เกิน 1 ครั้งต่อวินาทีต่อ viewer
  และคงชั้นเดิมไว้จนชั้นใหม่เริ่มโหลด (ไม่กะพริบเป็นสีดำ)
- สวิตช์ปิด หรือ server ตอบ 403 `IMAGERY_DISABLED` → ไม่มีชั้น GIBS ใดอยู่บน viewer
- ชิ้นที่ได้ 404 → โปร่งใส (ไม่แสดง error ของ Cesium); นับสัดส่วนชิ้นที่ไม่มีภาพต่อชั้นต่อ token
- เครดิตของชั้นที่แสดงอยู่ปรากฏในแถบเครดิตของ viewer

### 5.3 โหมดกล้องของ Sensor View

- แถบเครื่องมือเพิ่มกลุ่ม **Display: Camera | Sensor** (ป้าย `ours`) และปุ่ม **Zoom In / Zoom Out** พร้อมค่า "×8"
- พารามิเตอร์ของหน้าต่างเพิ่ม `display: "camera"|"sensor"` (ค่าตั้งต้น `"camera"`, รวมถึง workbook เก่าที่ไม่มีช่องนี้)
  และ `zoom ∈ {1,2,4,8,16,32,64,128}` (ค่าตั้งต้น 1; ค่าอื่นหรือค่าเสีย = 1) บันทึกกับ workbook
- **Camera**: ซ่อนทุก entity, data source และ primitive ที่ไม่ใช่ลูกโลกในหน้าต่างนี้เท่านั้น
  (เส้นวงโคจร จุดดาว ชื่อ กรวย/รอยของ sensor สถานี เส้น access เส้นวงโคจรแบบ Inertial) และไม่วาดวงกลมขอบกรวยบน HUD
  ชั้นบรรยากาศ ดาวพื้นหลัง และแสงกลางวัน/กลางคืนคงไว้
- **Sensor**: เหมือนก่อนงานนี้ทุกอย่าง (sensor §5)
- การซูมใช้ได้ทั้งสองโหมด: มุมกว้างด้านสั้น = `sensorViewShortFovDeg(α) / zoom`; วงกลมขอบกรวยของโหมด Sensor ใช้ค่าเดียวกัน
- ลูกล้อเมาส์ (ไม่กด Shift) บนภาพ = Zoom In/Out ทีละขั้น (Shift+ลูกล้อยังเป็นเลื่อนเวลาเหมือนเดิม) ตำแหน่งและทิศกล้องไม่เปลี่ยน
- HUD เพิ่ม 2 บรรทัด: มุมกว้าง (`FOV 3.6° ×8`) และแหล่งภาพพื้นโลก
  ("ภาพพื้นโลก: VIIRS NOAA-20 True Color 2026-11-11" ของชั้นบนสุดที่แสดง หรือ "ภาพพื้นโลก: Natural Earth II (ออฟไลน์)")
  ถ้าชั้นบนสุดไม่มีภาพเกิน 50% ของชิ้นที่ขอ ต่อท้าย "— ไม่มีภาพเวลานี้"
- สวิตช์ออนไลน์ปิดและอยู่โหมด Camera ที่ zoom ≥ 8 → HUD แนะนำ "เปิดภาพจริงได้ที่ View → Globe Manager" (บรรทัดเดียว)

## 6. ข้อผิดพลาดและความปลอดภัย

- ทุก request ของ browser ยังไป server ในเครื่องเท่านั้น; server เป็นจุดเดียวที่ต่อ GIBS และเป็นที่อยู่ของสวิตช์
- server ไม่รับ URL, host หรือ path อิสระ ประกอบ URL ปลายทางจาก catalog + ค่าที่ผ่านการตรวจ (§4.2)
- ไม่ตาม redirect ข้ามโฮสต์, จำกัดขนาด, ตรวจ magic bytes, ไม่ถอดรหัสภาพใน server
- ข้อความผิดพลาดทุกตัวเป็นภาษาไทยตามซองข้อผิดพลาดเดิม `{"code","text","field","detail"}`
- GET ของ route ใหม่ไม่ต้องมี Origin (ตามตัวกันเดิม) แต่ Host ต้องเป็นของเครื่อง (ตัวกันเดิม)

## 7. การทดสอบ

- **server** (ไม่ต่อเน็ต; ใช้ opener ปลอม + `no_network` เดิม):
  สวิตช์ปิด/ไฟล์เก่า → 403 และ opener ไม่ถูกเรียก; ค่าเสียทุกช่อง → 4xx ก่อนต่อเน็ต; URL ที่ประกอบตรงตัวอักษร;
  cache hit ไม่เรียก opener; 404 จำไว้; 403/429 พัก; 20 ครั้งติดพัก; ไฟล์ปลอม (HTML, ขนาดเกิน, ext ไม่ตรง) → 502 ไม่เขียน cache;
  เพดาน cache ลบเก่าสุด; PUT settings ครบเอกสาร + ไฟล์เก่าไม่มีช่องใหม่
- **web unit**: token เวลา (ขอบวัน UTC, ขอบ 10 นาที, เขตเวลาเครื่อง `TZ=America/New_York`); ลำดับชั้นและ index 0;
  สลับ token แล้วไม่สลับซ้ำเมื่อ token เดิม; params `display`/`zoom` แบบทนค่าเสีย; fov หารด้วย zoom; โหมด Camera ซ่อนทุกอย่าง
  เฉพาะหน้าต่างของตัวเอง; Globe Manager ส่ง PUT ทั้งเอกสารหลังยืนยันเท่านั้น; Daily window ส่ง `online_imagery` คืน
- **e2e** (ตัวกัน request นอกเครื่องยังทำงาน; server e2e สวิตช์ปิด):
  เปิด Sensor View → โหมด Camera, ไม่มี entity แสดง, Zoom In ×4 → fov ด้านสั้นลดเป็น 1/4 (คลาดไม่เกิน 1%), กล้องยังที่ดาว;
  Globe Manager แสดงรายการ, ติ๊กสวิตช์ → กล่องยืนยัน → ยกเลิก → settings ไม่เปลี่ยน
- **ตรวจบนหน้าจริง** (:8010 บนสำเนาข้อมูล): ทำเฉพาะเมื่อผู้ใช้อนุญาต B0 แล้ว

## 8. ความเสี่ยง

- ค่า TileMatrixSet/ext/รูปแบบเวลาใน §3.2 อาจผิด → B0 แก้ในตารางเดียว; ระหว่างนี้ทุกอย่างทดสอบด้วยค่าที่ตั้งไว้
- GIBS อาจตอบ "ไม่มีภาพ" ด้วยภาพว่างแทน 404 → B0 ยืนยัน แล้วเพิ่มกฎตรวจ (ขนาดเท่าภาพว่างที่รู้จัก) ถ้าจำเป็น
- ภาพรายวันของ VIIRS/MODIS เป็นภาพประกอบหลายรอบโคจร มีช่องว่างแถบดำใกล้ศูนย์สูตรได้ → Blue Marble เป็นชั้นรองข้างล่าง
- scenario พยากรณ์อนาคตไม่มีภาพจริง (ยกเว้น Blue Marble ที่คงที่) → HUD บอก
- หน่วยความจำกราฟิก: Sensor View ≤ 4 บาน, ชั้นภาพต่อ viewer ≤ 9; ชิ้นภาพ cache ใน browser ตามปกติของ Cesium
