# คุณภาพวงโคจรและการตรวจเทียบ

เปิดจากปุ่ม **คุณภาพวงโคจร / ตรวจเทียบ** มุมขวาบนของ Gpredict Web

ฟีเจอร์นี้อัปเดตวงโคจรที่นำไปคำนวณจริง พร้อมรายงานอายุ epoch และผลต่างกับแหล่งอ้างอิงที่มีสำหรับดาวแต่ละดวง การตรวจเทียบเป็นการวัดผล ไม่ได้นำผลต่างไปบวกชดเชยตำแหน่งหรือแก้ mean elements โดยอัตโนมัติ

## การอัปเดต

- เปิดอัตโนมัติเป็นค่าเริ่มต้น ทุก 2 ชั่วโมง ขณะเซิร์ฟเวอร์เปิดอยู่ แม้ปิด browser
- ตรวจรอบที่ค้างครั้งแรกภายใน 60 วินาทีหลังเปิดเซิร์ฟเวอร์ ตั้งรอบได้ 2–168 ชั่วโมง หรือปิดจากหน้าเดียวกัน
- ใช้ TLE sources, proxy, ตัวตรวจรูปแบบข้อมูล, กติกา rate limit และการ reload module เดิมของแอป ข้อมูล CelesTrak เข้าทาง OMM JSON จึงรองรับเลขแคตตาล็อก 6 หลัก
- ถ้าดาวน์โหลดไม่ได้ เก็บวงโคจรเดิมและแสดงคำเตือน ไม่ถือว่าการคำนวณสำเร็จหมายถึงข้อมูลสด
- ตารางบอกอายุ epoch จริงรายดวง แยกจากเวลาที่ดึงข้อมูล และแสดงจำนวนดาวที่เกิน 48 ชั่วโมง / 7 วัน ตัวเลขอายุเป็นข้อมูลประกอบ ไม่ใช่คำรับรองความแม่นยำ
- หลังอัปเดต เก็บ TLE เดิมและใหม่สูงสุด 32 ชุดต่อดวงสำหรับตรวจย้อนหลัง การเก็บซ้ำไม่เลื่อนเวลาที่พบชุดนั้นครั้งแรก
- กดอัปเดตเองได้ งานทำใน background และป้องกันการสั่งงานคุณภาพวงโคจรซ้อนกัน รอบที่ล้มเหลวจะลองใหม่ตามช่วงที่ตั้ง ไม่ส่ง request ถี่เพื่อข้ามข้อจำกัดของ source

## การตรวจเทียบ

| กลุ่มดาว | อ้างอิง | ความหมาย |
|---|---|---|
| GPS, GLONASS, Galileo, BeiDou | MGEX SP3 แบบ final/rapid จาก CDDIS; ถ้ายังไม่มี ลอง GPS rapid ของ IGS จาก BKG | ใช้เฉพาะตำแหน่ง observed; ไม่นับจุดที่ SP3 ติดธง predicted |
| ISS (NORAD 25544) | NASA/JSC/TOPO OEM | เป็นวงโคจรประมาณการจากผู้ควบคุมดาว ไม่ใช่ telemetry ที่วัดสด |
| ดาวที่ไม่มีอ้างอิง | ผลต่างจาก TLE ชุดก่อน ถ้ามี | บอกว่าผลคาดการณ์เปลี่ยนไปเท่าไร ไม่ใช่ความคลาดจากตำแหน่งจริง |

- GNSS ตรวจย้อนหลังวันที่ UTC ปัจจุบันลบ 2 วัน เพราะ SP3 observed ต้องรอเผยแพร่ ถ้ายังไม่พร้อมจะแสดงเหตุผลและลองใหม่ในรอบถัดไป
- จับคู่ NORAD ↔ PRN ผ่าน IGS satellite metadata ตามเวลาแต่ละจุด รวมกรณีเปลี่ยน PRN ไม่จับคู่ด้วยการเดาจากชื่อดาว
- แปลงเวลา SP3 จาก GPST เป็น UTC ครั้งเดียว โดยใช้ offset 18 วินาทีสำหรับช่วงปัจจุบัน
- ใช้ TLE ที่แอปเก็บไว้ก่อนวันตรวจถ้ามี และแสดง `forecast`; ถ้ายังไม่มี แสดง `hindcast` (ตรวจย้อนหลัง) โดยไม่อ้างว่าเป็นการทดสอบพยากรณ์ล่วงหน้าจริง
- เปรียบเทียบ GNSS ใน EarthFixed/ITRF; ISS เปรียบเทียบ NASA EME2000 กับ GMAT EarthMJ2000Eq เพื่อไม่เอาพิกัดคนละกรอบมาลบกัน
- ไม่ extrapolate ข้อมูลอ้างอิง และไม่ interpolate ข้ามช่องว่างของอนุกรมตามกติกา Lagrange ของ engine
- แสดงผลต่างตำแหน่ง 3D หน่วยเมตร (RMS, P95, Max) และ Az/El สำหรับ GNSS ที่อ้างอิง El ≥ 10°; Az ใช้เฉพาะ El < 80° เพื่อหลีกเลี่ยงความไม่เสถียรใกล้จุดเหนือศีรษะ ISS แสดงเฉพาะผลต่างตำแหน่ง 3D
- เก็บจำนวนคู่ข้อมูล ต้องมีอย่างน้อย 20 คู่จึงแสดง `compared`; น้อยกว่านั้นเป็น `insufficient_data` ไม่มีอ้างอิงเป็น `unverified` ไม่แทนด้วย error=0 และไม่ถือว่าผ่าน
- การกดตรวจเองใช้ module ปัจจุบัน งานอัตโนมัติใช้ดาวใน module ที่เปิดอยู่ ตรวจสูงสุด 200 ดวงต่อรอบ พร้อมบอกจำนวนที่ยังไม่รวม และใช้สถานีตั้งต้น (งานอัตโนมัติ) หรือสถานีของ module (งานที่เลือก module)
- ค่าต่าง TLE เดิม/ใหม่เทียบช่วง 24 ชั่วโมงข้างหน้า ทุก 5 นาที ด้วย GMAT แบบเดียวกัน จึงแยกผลของการเปลี่ยนข้อมูลจากการเปลี่ยนตัวคำนวณ

## การเก็บข้อมูลและ API

อยู่ใต้ `<GPREDICT_WEB_DATA>/quality/`:

- `settings.json`: การเปิดงานอัตโนมัติ รอบอัปเดต และการตรวจหลังอัปเดต
- `job.json`: งานล่าสุด ช่วงเวลาทำงาน สถานะและ error รวมเวลาที่พยายาม refresh ล่าสุด (งาน compare อย่างเดียวไม่เลื่อนรอบ refresh)
- `orbits.json`: TLE ที่แอปเคยนำเข้า พร้อม epoch, hash และเวลาที่พบครั้งแรก
- `latest.json`: ผลตรวจล่าสุด แหล่งอ้างอิง ช่วงเวลาที่ครอบคลุม และ warnings
- `references/`: OEM, SP3, metadata และเวลาที่ขอข้อมูล เพื่อจำกัดการเรียกซ้ำแม้ดาวน์โหลดล้มเหลว

| Method | Endpoint | หน้าที่ |
|---|---|---|
| GET | `/api/quality` | สถานะ อายุข้อมูล รายดวง และผลล่าสุด |
| PUT | `/api/quality/settings` | `{enabled?, interval_hours?, compare_after_update?}` |
| POST | `/api/quality/run` | `{action?: "cycle" / "refresh" / "compare", module?: "ชื่อ"}` ตอบ 202 แล้วติดตามผ่าน GET |

เวลาทั้งหมดบนหน้าตรวจระบุ UTC ชัดเจน และดาวน์โหลดผล JSON ได้ ปิดหน้าต่างไม่ยกเลิกงานที่เซิร์ฟเวอร์กำลังทำอยู่ เมื่อเซิร์ฟเวอร์หยุดจะหยุด GMAT ของงานคุณภาพก่อนปิด runtime

## แก้ข้อผิดพลาดที่พบในการ audit

- TLE ข้อความ Alpha-5 ถอดรหัสจริง เช่น A0744 → 100744 และ Z9999 → 339999 ไม่รวมดาวไว้ใต้หมายเลข 0
- ไม่ส่ง `Always out of range` เพียงเพราะไม่มี pass ในหน้าต่างข้อมูล 16 ชั่วโมงอีกต่อไป ใช้สถานะถาวรเฉพาะดาวที่เข้าเกณฑ์ GEO จาก TLE

## ตรวจรับ

ทดสอบ unit/API ครอบคลุมการแปลง GPST/UTC, การไม่นับ SP3 predicted, การปฏิเสธ OEM คนละกรอบ, cache fallback และ rate limit, archive/forecast/hindcast, missing truth, งานซ้อน และการตั้งรอบหลัง restart

การทดลองจริงบนเซิร์ฟเวอร์ทดสอบพอร์ต 8741 ใช้ฐานข้อมูลสำเนาและสถานี THBK ดึง MGEX ของวันที่ 14 พ.ย. 2026 ได้สำเร็จ เทียบ GPS 62339 และ Galileo 37846 ได้ดวงละ 280 คู่ พร้อมเทียบ ISS กับ NASA OEM ได้ 289 คู่ ส่วน Himawari-8 และ Arktika-M1 แสดง unverified ตามจริง ผลก่อนอัปเดตได้ Δ3D RMS ประมาณ 1,009 ม. / 695 ม. / 18,718 ม. ตามลำดับ เป็น residual ต่อข้อมูลอ้างอิงที่ระบุ ไม่ใช่ error ที่รับรองโดยการสังเกตภาคสนาม

รอบอัตโนมัติจริงเวลา 20:55 UTC อัปเดตดาวเดิม 782 ดวง เพิ่มใหม่ 64 ดวง ฐานข้อมูลเพิ่มเป็น 906 ดวง จำนวน TLE อายุเกิน 48 ชั่วโมงลดจาก 842 เหลือ 75 ดวง และเกิน 7 วันลดเหลือ 6 ดวง หลังอัปเดต ISS เทียบ NASA OEM ในช่วงเดิมได้ Δ3D RMS ลดจากประมาณ 18,718 เมตรเหลือ 2,094 เมตร ตัวเลขนี้ยังเป็นการเทียบกับ operator prediction จึงไม่อ้างเป็นผลวัดจากดาวจริง

ผลตรวจสุดท้าย: server 1,209 tests ผ่านทั้งหมด รวม integration ที่ใช้ GMAT จริง, frontend 1,490 tests ใน 86 files ผ่าน และ production build ผ่าน เปิดหน้าเว็บจริงและอ่านสถานะหน้าตรวจเทียบได้ครบทั้งรอบอัปเดต ผลรายดวง และข้อความแยกประเภทอ้างอิง
